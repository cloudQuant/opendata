## 1. 背景与目标

迭代2 的主线是“统一 Provider 架构与全量能力补齐”，当前仍处于开发/离线验收未完成、发布 NO-GO 的状态。继续扩大 provider 与模型分母之前，必须先处理已经暴露的**运行时正确性、安全边界和并发生命周期**问题；否则新增能力会建立在不可信的数据写入与会话语义之上。

本轮目标：

1. **安全基线可发布**：默认密钥、刷新令牌、越权读取、脚本导入、导出公式注入等 P0 风险清零。
2. **数据写入可信**：消除 `INSERT IGNORE` 静默吞错、行哈希歧义、列名冲突/截断、重试成功误判。
3. **执行链一致**：调度、重试、运行台账、水位回放、告警去重的状态机与文档契约一致。
4. **并发与异步可控**：修复共享 `AsyncSession`、事件循环阻塞、关闭顺序、超时语义等生命周期问题。
5. **质量债务不增长**：A2 零容忍继续 fail-closed；A1 棘轮只降不升；新增回归测试锁定本轮每个 P0/P1 修复。

非目标：

- 不新增 provider、不扩大 350 模型分母、不做发布验收。
- 不修改生产配置、数据恢复作业、用户工作树。
- 不对搬运代码 `_vendor` 做格式化或大规模重排。
- 不做与缺陷无关的全仓重构。

### 3.2 P1（本轮应完成）

- **会话与安全**：`Settings` 敏感字段未用 `SecretStr`；`api_key_failure_delay_seconds` 无下界；token blacklist `stop()` 后定时器重新自启；`/metrics` 无鉴权；Zip 成员解压无大小上限。
- **API 契约**：`create_interface`/`update_interface` 把 JSON 字段声明为查询参数；`update_task` 丢弃已验证的 pipeline 参数；`users.update_user` 可降级/停用最后一个管理员；删除用户与任务外键不级联；`stock_daily_publication` 把所有快照错误映射为 503；`temporal_identity` 顺序假设错误；`data_service` 成功/失败返回键不一致。
- **数据与 Provider**：`domains` 标识符正则使用 `$`；`ods_table()` 未按真实 source 校验长度；`protocol.acquire_instance_sync` 忽略 deadline；`decoders` 未包装 `BadZipFile` 等异常；`async_execution` 迟到完成/异常未按 deadline 归类；`minute_archive` 目录创建竞态；`value_transform` 在 decimal context 外做乘除/量化；`multi_request` 连接键冲突；`request_body` `max_rows` 用 `>`、指针覆盖嵌套字段；`spec` 未校验 `query_key` 唯一性；`provider_model_store` 单行写入未校验 InnoDB；`interface_loader` 在 `autoflush=False` 下去重失效。
- **Pipeline**：`watermark.replay_since` 未知 batch 返回最旧而非最新；`alerts` 先去重后升级，恶化不会升级；`jobs` 同步读阻塞事件循环、`second_source == authoritative` 归一化不完整；`reviewed_runtime` 缺少 `dispatch_backfill_execution` 覆盖；`scheduler` 返回伪造 `execution_id`、`_running_tasks` 仅按 task_id 覆盖；`scheduler_service` 零/负 interval、缺失 `run_date`、pending job 读 `next_run_time`。
- **并发**：`RetryService` 在后台任务复用共享 `AsyncSession`；`websocket.broadcast` 持锁做网络 I/O；`data_subscribe` 关闭顺序可能跳过 unregister；`corporate_events`/`jobs` 在 async 中做同步 DB I/O；`data_acquisition` 的 `wait_for` 无法终止线程且 Python 3.10 捕获异常类型不对。

### 3.3 P2（质量收口）

- Ruff 14,114 条中，优先处理高信号项：`F811` 重复定义 2、`S301` pickle 1、`S310` URL open 2、`S608` SQL 表达式 63、`ANN401` 35、`PERF203` 29、`B`/`SIM` 系列；纯 docstring/注解债务继续走 A1 棘轮，不逐条整改。

## 4. 工作包

### WP3-01 安全基线与会话（P0，5~7 人日）

**目标**：关闭 P0-01/02/05/07/11，建立不可绕过的生产配置与会话失效语义。

任务：

1. `secret_key`：改为 `SecretStr`；`model_config` 增加 `validate_default=True`；校验读取 `info.data["app_env"]` 而非 `os.getenv`；拒绝空值；`DEFAULT_SECRET_KEY` 改为不可用于签名的哨兵，非 production 也必须显式 opt-in。
2. 管理员初始化：`ADMIN_DEFAULT_PASSWORD` 缺失时 fail-fast；或生成后写入 0600 一次性文件并在日志中只提示路径，不再输出密码片段；确保首次登录强制改密。
3. 刷新令牌：`/auth/refresh` 校验 `is_revoked`，轮换时注销旧 refresh token；`/auth/logout` 同时注销 access + refresh；改密后按 `password_changed_at` 或 per-user token version 使旧令牌失效。
4. API Key 与发布授权：明确 `scopes` 只承载 domain；新增独立的 operation capability（或在 key 记录中增加 `operations` 字段并在签发时校验）；`require_published_access` 不再把 operation 塞进 domain scopes。
5. 并发冲突：注册、`init_db`、API Key `revoke/rotate` 使用条件更新或捕获 `IntegrityError` 并回滚，统一映射 409/400。
6. `Settings` 敏感字段统一 `SecretStr + repr=False/exclude=True`；`api_key_failure_delay_seconds` 增加 `ge=0.0` 与上限；blacklist `stop()` 增加 `_stopped` 标志；`/metrics` 增加网络/鉴权策略说明或默认关闭。

交付：

- 配置校验单测（三种来源：环境变量、`.env`、默认值）。
- 会话失效行为测试（刷新重放、登出后刷新、改密后旧 token）。
- API Key operation 授权测试（真实签发的 key 能读到授权数据集）。
- 并发注册/旋转测试（至少两个并发请求，断言无 500）。

验收：AC3-01~AC3-05。

### WP3-02 数据写入正确性（P0，5~7 人日）

**目标**：关闭 P0-03/04/09/10，确保“写入失败必须可见、重复必须可解释”。

任务：

1. `_insert_data`：用 `INSERT ... ON DUPLICATE KEY UPDATE id=id` 或显式捕获 duplicate-key；其他 `IntegrityError`/`DataError` 必须抛出；批次失败不得吞掉。
2. 列处理：保留列 `id`/`row_hash`/`created_at` 冲突时重命名或拒绝；`VARCHAR` 长度按全量/声明长度而非当前批次推断；超长值显式报错或截断并记录。
3. 行哈希：改为类型保真的规范序列化（JSON 显式 null、长度前缀或 `repr` 带类型），避免 `None`/`"None"`/`"nan"` 与 `|` 歧义。
4. 列名/表名：`clean_column_names` 去重并保证合法首字符；`generate_table_name` 前缀参与长度与字符校验；`safe_*` 改 `re.fullmatch`。
5. 重试/执行结果：`ScriptService.execute_script` 成功分支补齐 `rows_processed`；`DataService` 统一所有分支键集；`RetryService` 检查 `success`，失败走 `FAILED` 并继续重试链。
6. XLSX 导出：复用 `escape_csv_formula` 或显式写文本；CSV/XLSX 使用同一套序列化策略。
7. `.env` 写入：拒绝控制字符/换行/非法键；临时文件 + `fsync` + `os.replace` + 0600；异步回退用 `asyncio.to_thread` 并 `engine.dispose()`。

验收：AC3-06~AC3-10。

### WP3-03 执行、调度与台账一致性（P0/P1，5~6 人日）

任务：

1. `RetryService`：改为注入 `async_sessionmaker`，每个重试独立 session；任务完成回调清理 `_retry_queue`；`cancel` 后 `await` 并跟踪重试链。
2. `SchedulerService`：返回真实 `execution_id`；`_running_tasks` 以 `(task_id, execution_id)` 或任务对象身份为键；移除时校验所有权。

4. `watermark.replay_since`：未知/跨域 batch 回退到 `latest_batches`；子查询按 domain 限定。
5. `alerts.decide`：先算 rate spike，再决定是否被去重抑制；同一指纹恶化可升级。

8. `interface_loader`：内存 `seen_domains` 去重，必要时 `flush()`。

验收：AC3-11~AC3-15。

## 8. 风险、回滚与发布注意

| 风险 | 影响 | 缓解/回滚 |
|---|---|---|
| SECRET_KEY 校验收紧 | 旧部署可能启动失败 | 发布前注入 `SECRET_KEY`；提供启动自检与回滚开关（仅限非生产） |
| 刷新令牌注销 | 已登录用户需重新登录 | 发布说明；保留旧 token 一个宽限期开关（默认关闭） |
| `.env` 写入改为原子 | 权限/路径错误会显式失败 | 先备份 `.env`；失败返回 500 并保留原文件；提供手工恢复文档 |
| 行哈希算法变更 | 历史去重键失效，可能重复写入 | 先双写/旁路比对；迁移脚本按“旧哈希→新哈希”映射，不删除旧列 |
| enum 存储值调整 | 需要迁移 | 单独 migration，先读后写；保留回滚脚本 |
| 调度/重试状态机调整 | 在途任务可能被误判 | 灰度单实例；保留旧执行记录；提供重放/对账脚本 |
| 并发限制收紧 | 合法批量任务被限流 | 可配置阈值；先观测后启用阻断 |
