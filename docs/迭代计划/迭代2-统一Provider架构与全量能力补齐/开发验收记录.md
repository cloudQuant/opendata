## 3. 架构澄清

1. 350个provider×模型与33条现有capability是不同粒度。模型绑定应关联唯一注册能力，同域/频率/市场的模型不直接重复注册；34个描述符也不等于350模型实现。后续模型入口必须保留provider/model身份及服务语义。
2. DataScript与DataInterface没有可信映射，整数ID也可能碰撞。下载页面显式选择真实启用的数据接口，从接口目录取ID，再发送interface_id；不把脚本ID换名继续提交。无选择或目录失败不创建任务，成功以实际下载响应和任务查询为准。
3. SDK已有同步WebSocket，但发布metadata缺ws extra并漏声明loguru。保持独立消费者包、修正依赖，给现有frames extra提供惰性转换入口；安装验证隔离系统site及源码工作区的额外依赖。
4. 已有Fetcher均同步抽取。统一异步契约使用受限线程；取消后尚在执行的阻塞调用继续占额度，避免假取消造成无界后台工作。
5. 调度当前刻意写入源原始ODS。直接以规范化fetch_async替换raw callback会改变列/单位；生产调度使用同一Fetcher的受控raw async入口，再保留原有ODS转换。服务查询仍通过共享标准化入口。任意旧同步注入回调的兼容性不等于它具备非阻塞保证。
6. SDK隔离wheel构建曾直接读取SDK根路径，生成build/lib使静态源扫描多算两个文件。已将build输入改为仓外白名单副本，仅删除有归属证据的本次构建产物；保留原有缓存和用户文件。以后独立安装证据不能污染主树。
