## 4. 逐模型工作单与估算

来源大包不是一个worker任务。每个工作单列OBB2身份、官方事实来源、契约卡、编辑路径、依赖、正/反例、验证命令、预期产物和回滚边界。优先一个小模型或同一接口族的少量模型；FMP69与Intrinio38必须拆分。

旧计划175—195人日没有展开完整350条契约/存储/PIT/迁移，不作交付承诺。WP2-00/01/06先建立既有源扩展、确认为无Key宏观源、商业源三个垂直切片，至少6个工作单覆盖simple、分页多市场、复杂时点/事件三类；不具备真实访问条件的切片将live校准单列BLOCKED，不用fixture替代真实耗时。选择1—2个经权利与费用核对可取得Key的源优先校准卡→fixture→真实响应，当前未决定采购或申请。

完成3个切片/至少6单后必须重新估算并冻结阶段容量；其后每完成20单滚动复算。若预计实现+评审+离线验证总工时超过已批准阶段容量，或同复杂度单模型P50较切片基准上升>25%，暂停新增批次派单，提交资源/顺序/阶段组成调整方案后再恢复；当前没有批准的总工期/人日，需先形成容量基准，不能将未知阈值写为已满足。报告开发、共享核心、live等待三个分量，不缩350分母。

排期计算为：各工作单实现+评审+离线验证之和 / 有效并行度，再加真实来源等待、共享核心与发布串行阶段。30是代理名额上限，不是有效并行度；不能把核心/主模型评审/对照工作简单除以30。保留迭代1的10%—15%上游同步/失效维护预算。
