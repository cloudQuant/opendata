## 1. 本轮明确的架构决定

| 决定 | 迭代2目标 |
| --- | --- |
| 独立 provider | 固定 OpenBB 基线的32个 provider，加项目自有 AkShare、THS，共34个目标 provider；独立的职责和注册单元不要求拆成34个发行包 |
| THS 目录整合 | opendata_fuyao 的传输、端点、dump 和映射代码迁入 opendata/data/providers/ths/ |
| AkShare 目录整合 | opendata_http 搬运代码迁入 opendata/data/providers/akshare/_vendor/；保留独立 MIT 子树及来源清单 |
| 单一框架 | opendata/data/ 承担自研核心；复用现有 Fetcher、契约、ProviderRegistry、domains、pipeline、API，增加统一 Provider 定义 |
| 全量能力 | 固定基线350个 provider×模型条目逐项评估、补齐实现和对照；无 Key 可推进实现和离线验证，真实对照保持未验证状态 |
| 对外兼容 | source、domain、REST/WS 和独立 opendata_client 契约保持；旧顶层 Python 包导入按显式迁移清单收口 |

## 4. 阶段与交付口径

开工先完成可恢复隔离、base门禁工具链对齐、当前树完整gate读数及外部条件预检。2A完成目录整合和统一 Provider 核心；2B补齐现有5个来源及7个其他宏观来源；2C完成5个商业/聚合来源；2D完成其余15个来源；2E关闭适用的迭代1缺口并完成同一冻结树上的发布验收。逐源权利登记、Key决策和外部条件确认提前推进；官方复权合格样本在条件具备时于2B开始采集，冻结树验收仍在最终阶段完成。2C与2D的独立工作可在2A完成、对应标准模型确定后并行。

异步采用统一入口包装、模型/来源级显式适配：原生async与有界阻塞SDK适配共用标准化链；不承诺把34源所有底层SDK改成原生异步。子代理最多30个（含后代，不含主代理，运行时更低限制优先），共享核心、评审及真实对照不按30简单均摊。

分别报告 DEV_DONE（实现和离线回归完成）、SOURCE_VERIFIED（官方/真实来源对照完成）、DEPLOYMENT_VERIFIED（指定环境落地完成）。只有完整范围及适用验收项都通过，才报告迭代2整体 PASS。缺 Key、网络不可达、无合格样本等分别留 BLOCKED 或 NO_READING；不删除对应任务或缩小分母。

2026-10-08用户进一步明确阶段顺序：当前先完成全部开发与离线验收，然后单独安排真实来源对照和部署验收。当前阶段仍覆盖全部34个Provider、350个固定模型条目、202个模型身份及适用工作包；不能把仅已实现的10项当作完整开发范围。满足全量实现、离线正反例、服务入口、发行及质量判据后可独立报告开发/离线阶段完成；SOURCE_VERIFIED、DEPLOYMENT_VERIFIED和发布结论继续分别记账。缺实际来源或生产证据不伪造通过，也不阻止其余离线开发。
