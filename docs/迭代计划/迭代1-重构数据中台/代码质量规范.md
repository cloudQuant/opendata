> 版本：v1.2

> 状态：生效（迭代1 起约束全部新增代码）
> 基准：适配自 `bt_api_py` 质量体系，并按 opendata 仓库现状（继承 akshare_web 遗产）调整
> 关联：`需求文档.md` NFR-7、`实施计划.md` A0.10、`验收文档.md` AC-17
> v1.2（A0 实施回填）：把已实现的机制写入规范，消除"规范写的"与"仓库里跑的"不一致——①§7 增列

## 0. 核心原则

1. **fail-closed**：所有质量门禁默认阻断；工具缺失、配置缺失、快照缺失、证据缺失一律视为失败，不得静默放行。
2. **分层适用**：质量要求按**代码来源**（自研/搬运）与**代码新旧**（存量/新增）两个维度分层——**继承项目不能套用"新项目零债务"假设**（§1）。
3. **债务不增长**（棘轮）：存量债务快照固化，只降不升；范围缩小或静默变更即失败。
4. **触碰即达标**：任何被修改的存量文件，一次性满足新增代码标准。
5. **证据文化**：任何"通过"声明必须附可复算命令与真实输出；历史证据只作参考，不作当次通过依据。
6. **反空壳测试**：测试必须锁定行为（黄金向量/真实报文/错误翻译），禁止自指与单断言空壳（§5）。

## 1. 分层适用范围

| 层 | 范围 | ruff | mypy | bandit | docstring | coverage |
|----|------|------|------|--------|-----------|----------|
| **A1 自研-存量** | `opendata/`（原 app/）**未被本迭代修改的文件** | 债务 ≤ 基线快照 | 债务 ≤ 基线快照 | 债务 ≤ 基线快照 | 不强制 | 不设新阈值（记录现状 84%） |
| **A2 自研-新增/触碰** | 新增文件 + **被修改过的存量文件**；`opendata/data/`、`pipeline/`、`opendata_fuyao/`、`opendata_providers/`、`scripts/` | 全规则集（§2.1）零违例 | 严格（§3）0 errors | 全量 | Google 风格 100% | ≥85%（statement+branch） |
| **B 搬运代码** | `opendata_http/`（akshare 搬运） | 仅 E/F（语法与未定义名），不格式化不重排 | 排除 | 排除（**安全审计另行专项，见 §4**） | 不要求 | 排除（以一致性对照替代） |
| **C 测试代码** | `tests/` | 全规则集但豁免 S1xx/S2xx、ANN 系列 | 渐进（不强制） | 豁免 S | 测试类/docstring 见 §5 | —（本身即覆盖度量源） |
| **D 生成产物** | codemod 报告、alembic 迁移模板 | 排除 | 排除 | 排除 | — | — |
| **E 前端** | `frontend/` | ESLint（沿用现有配置） | `vue-tsc --noEmit` | — | — | 基础用例（§9 gate 纳入） |

> **为什么 A 层要拆 A1/A2**：`opendata/`（原 `app/`）是 akshare_web 遗产，共 67 个源文件；实测当前 mypy 非严格（`disallow_untyped_defs = false`）、ruff 忽略含 `F821`、覆盖率 70% 阈值（实测 84%）。若按"新项目零债务"要求一步达标（mypy 严格 0 errors + 全规则集 + 85% + docstring 100%），估算需 30~40 人日，会让地基里程碑直接卡死或被迫放水——两者都会破坏 fail-closed 的信用。故按"**存量棘轮 + 增量零容忍 + 触碰即达标**"执行。
>
> **搬运层理由**：akshare 源码无类型注解、无规范 docstring；强行满足 A 层标准会诱发大规模改写，破坏与上游 diff 同步能力（设计 §5.2 规则 7）。搬运质量由**一致性对照（FR-18）**保证，不由静态检查保证。

## 2. Lint 与格式（ruff）

### 2.1 自研代码规则集

```toml
[tool.ruff]
line-length = 100
target-version = "py310"
exclude = ["opendata_http", "alembic/versions", "frontend", ".venv"]

[tool.ruff.lint]
select = [
    "E", "W",   # pycodestyle
    "F",        # pyflakes（**含 F821 未定义名，不得忽略**）
    "I",        # isort
    "N",        # pep8-naming
    "UP",       # pyupgrade
    "B",        # flake8-bugbear（含 B904 raise-from）
    "C4",       # flake8-comprehensions
    "SIM",      # flake8-simplify
    "TC",       # flake8-type-checking
    "RUF100",   # unused noqa
    "S",        # flake8-bandit security
    "PERF",     # perflint
    "ANN",      # 类型注解
    "D",        # pydocstyle（Google 风格）
]
# 例外必须逐条注释理由
ignore = [
    "B008",   # FastAPI Depends() 是框架惯用法，97 处误报会淹没真信号
]
```

> **相对现有配置的关键变更**：现有 `pyproject.toml` 的 ignore 列表含 `F821`（未定义名）、`E402`、`E722`、`E712`、`F841` 等——**`F821` 必须移除**（静态检查放过未定义名是最高风险的一类漏检）；其余各条按命中数逐条评估后决定"修复 / 短期白名单 + 收敛计划"，不得长期整体忽略。

### 2.2 搬运代码

```toml
[tool.ruff.lint.per-file-ignores]
"opendata_http/**" = ["E501"]   # 上游长行保真
```

- 搬运代码**禁止** `ruff format`、禁止 isort 重排——保持与上游逐行可 diff。
- **`.pre-commit-config.yaml` 必须加 `exclude: opendata_http/`**：现有 pre-commit 含无 exclude 的 `ruff-format` hook，若不排除，改名后会对搬运代码全量重排，直接违反本节并破坏 §7 棘轮前提。
- 对搬运代码只跑 `ruff check --select E,F opendata_http`，其债务进棘轮快照（§7）。

### 2.3 格式

- 自研代码 `ruff format` 全量通过（CI 阻塞）；**A1 存量文件在被触碰前不强制重排**（触碰后按 A2 处理）。

## 3. 类型检查（mypy）

- **A2 层配置（严格起步）**：

```toml
[tool.mypy]
python_version = "3.10"
explicit_package_bases = true
disallow_untyped_defs = true
disallow_incomplete_defs = true
no_implicit_optional = true
warn_redundant_casts = true
warn_unused_ignores = true
strict_equality = true
check_untyped_defs = true
warn_return_any = true
```

- **目标：A2 层 0 errors**；**A1 层**建立基线快照（error 数与按文件的分布），只降不升。
- `ignore_missing_imports = true` 仅限无 stub 的第三方库；禁止用 `Any`/`cast`/`type: ignore` 压债。
- 搬运层（B）整体 `exclude`，不参与 mypy。
- 渐进收紧条款：若引入的第三方依赖触发系统性误报，允许**按模块** override 放宽单条规则，必须在 pyproject 内注释理由与回归计划；禁止全局 `disable_error_code` 兜底。

## 4. 安全扫描（bandit）

- A2 层全量：`bandit -c bandit.yaml -r opendata opendata_fuyao opendata_providers scripts`。
- 例外必须**精确到行级**且带理由注释。
- 凭证类（S1xx）：`.env` 注入、日志脱敏、API Key 哈希落库（设计 §10.3）为硬约束，违反即一票否决。
- **搬运层安全专项（新增排期）**：`opendata_http/` 虽不纳入日常 bandit，但需在 **A2 里程碑执行一次性全量扫描**（含 `mini_racer` 执行站点 JS 的 40 个文件、子进程、动态导入面）并人工 triage 留档；JS 执行点须登记来源与 sha256。

## 5. 测试基线（反空壳）

### 5.1 空壳测试判定（发现必须修掉）

1. **自指测试**：测试体内重新实现被测算法与实现自比较（永远绿）。改为断言**预计算的黄金向量**。
2. **单断言空壳**：仅断言类名/常量。必须覆盖行为。
3. **`inspect.getsource` 形式检查**：断言源码文本，重构即破坏。改为行为测试。

### 5.2 模块分档最低基线

| 档 | 适用模块 | 最低要求 |
|----|---------|---------|
| **T1** | `opendata_fuyao/`（客户端）、`opendata/data/http_client.py`、契约层核心 Fetcher | ①错误翻译：真实响应信封样例断言错误码 → 异常映射，≥3 用例（含成功不抛）②黄金向量：认证头/签名构造断言预计算值 ③normalize：真实报文 → 标准化模型逐字段断言，≥3 用例 |
| **T2** | 有 Key 的 providers | ①错误翻译 ≥2 ②normalize 真实报文 ≥2 |
| **T3** | 纯公开只读 providers | normalize 真实报文 ≥2（录制回放样本） |
| **T4** | 服务层（`ods_writer` / `reconciliation` / `dwd_merge` / `pipeline` / `registry` / `partition` / `freshness`） | 行为测试：key 级幂等 upsert、合并规则、差异捕获、**口径映射反例**、降级路由、断点续跑、**修订传播**、**跨年分区写入**；禁止 mock 被测对象自身 |
| **T5** | API 层（REST/WS 路由） | 集成测试（httpx AsyncClient / WS 测试客户端），覆盖鉴权、分页、错误码、**参数注入用例** |

- **真实报文来源**：fuyao 用官方文档示例 + 联调录制；providers 用录制回放样本（与 FR-18 一致性对照共享样本库）；禁止手造"理想报文"替代真实样本。
- 测试命令基线：`python -m pytest tests -v -n 8 --cov-branch`（对齐多进程并行惯例）。
  - **前置依赖**：`pytest-xdist` 必须写入 dev extra（现有 `requirements.txt`/`pyproject.toml`/`pytest.ini` 均未声明，按文档写法 `make gate` 必然失败）。
  - `pytest.ini` / `pyproject.toml` 的 `addopts` 中 `--cov=app` 需同步改为 `--cov=opendata`。

## 6. 覆盖率门禁

- **A2 层** statement+branch ≥ **85%**，fail-closed。
- 分模块下限（进 pytest 配置）：`opendata/data/`、`opendata/pipeline/`、`opendata_fuyao/` ≥ **90%**（纯逻辑，可测性高）。
- **A1 存量**：不设新阈值，以**基线快照**管理（现状 84%，`fail_under` 从 70 上调至 84 并声明"只升不降"）；被触碰的文件按 A2 标准计入。
- **B 层**不计入 coverage（由一致性对照替代）。
- 覆盖率报告（xml + html）必须非空并归档为 CI artifact。

## 7. 棘轮机制（债务只降不升）

- **快照文件**：`docs/quality/ratchet.json`，记录四类债务计数与**扫描范围**：
  - B 层（搬运代码）lint 债务
  - A1 层 mypy errors 与 ruff 违例
  - 直连 HTTP 调用数（搬运包内 `requests.*` 调用点，设计 §5.2 规则 3 的渐进收口指标）
  - A0 首次冻结值（实测）：`ruff_selfdev=404`、`mypy_selfdev=35`、`bandit_selfdev=6`、`ruff_ported=1418`、`direct_http_ported=1270`
- **零依赖基线**：`docs/quality/zero-dep-baseline.json`。集成层的 `import akshare` 由 FR-17（1B-B5）
  清除，在此之前按"逐条登记 + 只降不升"冻结；与棘轮同构，但独立成文件以示"这是待消除的债务"而非
  "长期接受的债务"。
- **检查规则**：
  - 当前计数 > 快照 → 失败；
  - 扫描范围静默缩小 → 失败（包从扫描面消失、文件数下降）；扫描面**新增文件属正常开发**，由 A2 零容忍门禁覆盖；
  - 工具版本变化 → 失败（度量标准变更需显式确认）；
  - 仅当全部范围未增长且至少一项下降时，方可 `--update` 固化新低；范围扩张必须显式 `--force-update` 并走审查。
- **A2 层零容忍**：不设债务快照——任何 ruff/mypy/bandit 违例直接阻断（`make a2-check`）。

## 8. 公共 API 质量

## 9. 质量检查命令（Makefile 目标）

> **与现有 Makefile 的合并方案**：现有目标为 `lint / format / security / deps-audit / typecheck / quality / test / test-cov / frontend-* / quality-full / pre-commit`。本规范统一如下（**保留现有目标名以避免破坏既有习惯**，新增项补充）：

| 命令 | 说明 | 与现有关系 |
|------|------|-----------|
| **`make a2-check`** | **A2 零容忍门禁**：对"新增/改动文件"（相对 `docs/quality/baseline.json` 记录的基线 commit）跑 ruff 全规则 + format + mypy + bandit，任一违例即失败。CI 上若设有 `A2_BASE_REF`，基准取该 ref 的 merge-base 与基线 commit 中**较新者**——否则目标分支早于基线时（如 dev→master）会把冻结的 A1 存量整库划入 A2 而误判 | 新增（**门禁项**） |
| `make lint` | ruff check（A+C 层全规则；B 层 E/F） | 沿用，路径 `app/` → `opendata/`；**开发者视图，不进门禁** |
| `make format` / `make format-check` | ruff format（仅 A2+C 层，**排除搬运包**） | 沿用 + 新增 check |
| `make typecheck` | mypy（全树） | **沿用现有名**（原计划名 `type-check` 作废）；**开发者视图** |
| `make security` | bandit（全树） | **沿用现有名**（原计划名 `security-scan` 作废）；**开发者视图** |
| `make deps-audit` | pip-audit | 沿用 |
| `make test` | pytest `-n 8`，默认 `not e2e` | 沿用，补 `-n 8` |
| `make test-cov` | pytest `-n 8 --cov-branch` + 阈值门禁 + 报告归档 | 沿用 |
| `make quality-ratchet` | 棘轮检查（CI 阻塞） | 新增 |
| `make public-api-quality` | 公共 API docstring/注解覆盖率统计 | 新增 |
| `make zero-dep-check` | 零上游依赖断言（AST 口径 + 自测） | 新增 |
| `make brand-check` | 品牌残留与 `app/` 旧包名残留检查 | 新增 |
| `make frontend-lint` / `frontend-typecheck` / `frontend-test` | 前端三项 | 沿用，**纳入 gate** |
| `make gate` | **门禁聚合**：brand-check / zero-dep-check / a2-check / quality-ratchet / public-api-quality / test-cov / 前端三项，逐项阻断 | 新增（`quality` 目标保留为 `a2-check` 的别名） |

> **为什么门禁用 `a2-check` 而不是 `make check`（lint+typecheck+security）**：A1 存量自带静态检查债务，
> 规范要求以**棘轮**管理而非一步清零（§1）。若把全树静态检查放进 `gate`，要么永久红灯、要么被迫放宽
> 规则——两者都会破坏 fail-closed 信用。因此门禁由 **A2 零容忍（`a2-check`）+ A1 棘轮
> （`quality-ratchet`）** 共同承担；全树视图保留给开发者观察债务分布。

## 10. CI 门禁（fail-closed 聚合）

- **CI 平台：GitHub Actions**（仓库当前无任何 CI，需在 A0 从零搭建）；集成测试使用 `services: mysql:8.0`。
- `quality-gate` job 逐项运行 §9 的 `make gate` 并**逐项显式阻断**；任何子项失败不得被汇总结果掩盖。
- **零上游依赖断言（AC-16）并入 gate**：**分层 AST 口径**——`python scripts/codemod/verify_no_akshare.py` **只扫运行时包**（`opendata/`、`opendata_http/`、`opendata_fuyao/`、`opendata_providers/`、`opendata_client/`）的 `Import`/`ImportFrom`/`importlib.*`/`__import__` 调用与"纯模块路径"字符串常量，忽略注释与 docstring。该扫描面等价于把 `scripts/codemod/`、`tests/`、`docs/`、`README.md`、`THIRD_PARTY_NOTICES.md` 排除在外。**扫描面静默变更即失败**（包集合、文件数、工具版本入库）；扫描器需含"故意违规样本 + 合规样本"自测（`--self-test`）。
  - 存量违反冻结在 `docs/quality/zero-dep-baseline.json`（A0 时 6 处 `import akshare`，属 FR-17 待清除）：**只降不升**，新增即失败。
  - 另需**正向证据**：在未安装 akshare/openbb 的干净环境中跑 P0 域集成测试。
  - 字符串常量引用（如 `"akshare.data"`）由 codemod 改写 + 扫描器覆盖。
- **secret 扫描**：gitleaks/detect-secrets 进 pre-commit 与 CI（含全历史扫描）。
- pre-commit：ruff + 空白符 + YAML/JSON 校验 + **secret 扫描**；**`exclude: opendata_http/`** 用于 ruff-format；mypy/bandit 放 CI（本地可选）。
- 性能基线（可选，不阻塞本期）：对 `ods_writer` 批量 upsert、`dwd_merge` 建 pytest-benchmark 基线。

## 11. 提交与审查约定

- Conventional Commits；涉及 `opendata_http/` 的搬运提交须注明来源模块与文件数。
- 质量声明必须附证据（命令 + 输出摘要 + 日期）；"此前通过"不等于"本次通过"。
- 新增第三方依赖须在 PR/提交说明中声明用途与许可证兼容性（BSL/MIT 边界，设计 §1.3）。
- **搬运前凭证检查**：搬运文件中若含上游硬编码凭证，须替换为环境变量或登记到 `port-report.md` 后再入库。
