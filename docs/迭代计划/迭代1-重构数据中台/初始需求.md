## 1. 背景与定位

### 1.1 项目定位

opendata 是新创建的**数据中台**项目，为 backtrader、ai-for-investor、bt_api_py 等各个项目提供统一的数据支持，以 API 接口（REST + WebSocket）对外服务。

本迭代以 `akshare_web` 的完整拷贝为起点进行重构，同时将 `bt_api_py` 迭代09（历史数据获取）的规划**整体迁移到 opendata 落地**。

### 1.2 三方关系（现状）

| 项目 | 现状 | 与本迭代的关系 |
|------|------|----------------|
| **opendata** | `akshare_web` 的逐字节完整拷贝，重构尚未开始 | 本迭代的实施主体 |
| **bt_api_py** | 迭代09 五份文档已完成规划但代码未实施（`bt_api_data` submodule 不存在） | 其规划迁入 opendata 落地；bt_api_py 后续经 opendata API 取国内历史数据 |
| **消费方** | backtrader（backtrader_web）、ai-for-investor 等 | 通过 opendata 的 REST/WS API 取数 |

### 1.3 现状盘点（重构起点，2026-09-22 实测）

opendata 当前代码（拷贝自 akshare_web，零改动）已具备：

- **后端**：FastAPI（15 个 API 路由文件，挂载 `/api/v1`）、SQLAlchemy 2.0、alembic 迁移、MySQL 双库
- **前端**：Vue 3 + TypeScript + Vite + Element Plus + Pinia（**13 个视图页面** + `admin/` 子目录）
- **数据库**：MySQL 8.0 双库——主库（用户/任务/元数据）+ 数据仓库（脚本输出），可选 Redis
- **调度**：APScheduler 3.x（AsyncIOScheduler，内存 job store，启动时从 `scheduled_tasks` 表重载）
- **WebSocket**：仅 `/ws/executions`（任务执行状态推送，JWT 认证、心跳、广播）
- **数据获取**：`app/data_fetch/` 框架十大类目录（stocks/funds/futures/...）中**仅 1 个脚本落地**（A 股日线 `stock_zh_a_hist`）
- **内嵌 akshare 源码**：根目录 `akshare/` 为 akshare 库拷贝（**394 个 `.py` 文件 / 98,396 行 / 39 个子目录 / 4 个顶层模块**），`pyproject.toml` 的 `packages = ["akshare"]` 使 `import akshare` 解析到仓库内副本
- **测试**：`tests/` 84 个测试文件，1324 个用例（1317 通过 / 7 失败），覆盖率 84%

**实测补充（影响搬运设计）**：

- `akshare/data/` 目录**不存在**；非 `.py` 资源仅 6 个文件：`movie/jm.js`、`air/crypto.js`、`air/outcrypto.js`、`stock_feature/ths.js`、`file_fold/calendar.json`（124K）、`.DS_Store`
- `akshare/datasets.py` 使用 `resources.path("akshare.data", file)`，因该包不存在，`get_ths_js()` / `get_crypto_info_csv()` **当前即已断链**，被 20 个模块引用
- `requests.get/post` 直连调用 **1,270 处**（分布 301 个文件）；集中式 `akshare/request.py` 仅 117 行 2 个函数、仅 4 个文件引用
- 40 个文件使用 `mini_racer` 执行站点 JS
- `akshare/stock/cons.py:8` 存在**上游硬编码的真实 token**，搬运时须处置

主要欠账：品牌未改（pyproject 项目名仍是 `akshare`、版本 1.17.91、运行时名 `akshare_web`、前端 title 同）、许可证仍是 MIT、无 `ods_` 表、无数据订阅 WS、无多源校对、git 仓库仅跟踪 2 个文件（`.gitignore`、`LICENSE`）尚未做首次完整提交、存在 `LICENSE copy` / `".gitignore copy"` 等拷贝残留。

## 2. 目标

把 opendata 建成"**数据获取内化 + 落库 + 服务化**"的完整数据中台：

1. **源码级内化数据获取能力**：akshare（MIT，按需搬运）+ OpenBB（AGPL，仅借鉴架构、provider 自研）+ 同花顺扶摇 API（自建客户端），整合完成后运行时**零 akshare / openbb 外部包依赖**。
2. **跑批与定时任务体系**：数据域按调度落 MySQL，支持断点续拉与失败重入。
3. **API 服务化**：REST 查询 + WebSocket 订阅增量，所有落库数据均有对应接口；配套最小 Python 客户端，消费方不手写协议。
4. **数仓分层与多源校对**：数据落 `ods_xxx` 表（一源一表）；同域多源交叉校对发现差异；合并出 `dwd_` 统一层供查询，复权口径由服务端统一提供。
5. **品牌与合规**：项目全链路改名 opendata；许可证改为 BSL 1.1（个人免费使用，机构和商用需要授权）；建立数据源权利登记与免责声明。

## 4. 任务拆解（六大工作块）

### WB-0 品牌、合规与工程地基

- pyproject 项目名 `akshare` → `opendata`（版本重置 `0.1.0`）；Python 包 `app/` → `opendata/`；`app_name`、`.env*`、前端 title、nginx、docker-compose、systemd service 同步改名
- MySQL 双库改名：主库 → `opendata`、数据仓库 → `opendata_data`（**四处配置面同步收敛**：`config.py` 默认值、`.env.example`、`docker-compose.yml`、`init.sql`）
- **凭证与敏感文件隔离**：`.gitignore` 改为 `.env*` + `!.env.example`；排除 `.idea/`、`LICENSE copy`、`.DS_Store`；pre-commit 增加 secret 扫描；**首次完整提交前 dry-run 审计**
- 许可证 MIT → BSL 1.1（四要素齐备）；`THIRD_PARTY_NOTICES.md`（akshare MIT 声明 + 来源 commit）
- **数据权利合规**（D11）：数据源权利登记表、免责声明、条款核查
- 清理拷贝残留；git 首次完整提交；CI 基线（**仓库当前无任何 CI，需从零搭建**）
- **工程质量门禁搭建**（按 D12 分层）：ruff/mypy/bandit 分层配置、Makefile 质量目标、CI fail-closed 聚合、存量基线快照

### WB-1 数据获取层内化

- 统一数据契约：标准化模型（行情/复权因子/复权事件/财务/指数成分/**标的元数据/交易日历**/宏观/基金/期权/期货基本面）+ 三段式协议 + 能力声明
- provider 注册表与源路由（`source="auto"` 按权威度+可用性选择与降级）
- `opendata_http`：akshare **按需搬运**（D9），请求层渐进收口，异常规范化；codemod 工具链；`upstream.lock` + **manifest 清单**（文件/资源/哈希）
- `opendata_fuyao`：同花顺扶摇 API 客户端（认证、信封解析、错误码映射、限流退避、market-dumps 全市场批量）
- `opendata_providers`：OpenBB 风格 provider 自研（零 OpenBB 源码），按消费场景分批
- 跨源请求治理（统一超时/重试/并发上限/限流退避/失败分类）与缓存增量（**缓存只存原始响应**，水位以 ods 为准）

### WB-2 数仓与落库体系

- `ods_` 建表规范（一源一表、**源原始列保真 + 元数据列**）与 `dwd_` 合并规范（契约模型列 + 权威源优先 + `source` 留痕 + `_diff_flag`）
- **数据仓库 DDL 由独立 alembic 环境管理**（不再用启动时 ensure-table）
- 大表按 `trade_date` 年 RANGE 分区 + **分区自动维护任务**
- 多源交叉校对作业：**经契约模型归一化后比对**，产出差异报告 + 告警治理（白名单/去重/分级）
- **新鲜度监控**：每日检查各域是否含最近交易日数据，缺失即告警
- 旧机制迁移：`interface_loader` 与 `data_acquisition` 向 provider 注册体系迁移；`data_interfaces` / `data_scripts` 元数据表与前端页面适配

### WB-3 跑批与调度体系

- 沿用 APScheduler，增强：数据域 pipeline 编排（fetch → ods 落库 → 校对 → dwd 合并 → WS 推送）
- 断点续拉与进度持久化（大任务如全市场 10 年日线可中断续跑）
- 失败重试、单标的失败不阻断全局、失败清单**一键重试**（前端）
- **新鲜度与失败告警矩阵**（跑批失败、连续失败、分区缺失、磁盘水位）

### WB-4 API 服务层

- REST 查询 API：按数据域查询（标的/日期区间/源/分层/**复权口径**/分页/过滤/导出）
- **数据目录与新鲜度接口**（capabilities + freshness 合并），供前端数据目录页使用
- WS 数据订阅：`/ws/data/subscribe`，**meta 模式为一等公民**（full 模式标注实验性）
- **最小 Python 客户端** `opendata_client/`（git 依赖安装，不发 PyPI）：封装 REST 分页/认证/复权参数与 WS 订阅
- 消费方 API Key（含 `expires_at`）
- OpenAPI 文档完善 + 错误业务文案表

### WB-5 验收与消费方对接

- 搬运一致性对照（opendata_http 输出 vs akshare 原实现，录制回放样本）
- 真实消费方打通（backtrader_web 经 API 取 A 股日线完成回测数据准备）——**时点提前至迭代 1B**
- 端到端验收（详见 `验收文档.md`）

## 6. 非目标（本迭代明确不做）

- **不复制 OpenBB 源码**：AGPL-3.0 传染性会把整个仓库拖入 AGPL，只借鉴接口形态与命名，实现全部自研
- **不做实时行情接入与转发**：opendata 定位历史/批量数据中台
- **不做交易/下单能力**
- **不支持多 worker 部署**（D8）：本期单进程合一；分布式锁与多进程推送总线列为演进项
- **不搬运与金融数据无关的 akshare 子模块**（D9）：movie/news/nlp/air/fortune/cost/article/tool 进按需接入清单
- **不承诺冷门子模块与上游 pending 端点的可用性**：失效即弃（标记 deprecated、移出路由、不修复）
- **不发布 PyPI**：opendata 以服务形态部署；客户端以 git 依赖提供
- **不做完整数仓分层（dws/ads）**：本迭代只到 ods + dwd
- **不动 bt_api_py 的 CTP 采集链路**
