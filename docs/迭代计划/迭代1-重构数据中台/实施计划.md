## 2. 全局约束

1. **许可红线**：零 OpenBB 源码进入仓库；akshare 搬运保留 MIT 声明；自研代码不置于搬运包内；整合完成后运行时零 akshare/openbb 依赖（CI 分层 AST 断言）。
2. **业务连续**：既有认证/任务/执行/表查询/前端能力在改造期间保持可用（渐进迁移，兼容期开关）。既有开发库数据可弃（项目未投产）。
3. **测试与质量**：全部新增代码受 `代码质量规范.md` 约束；`make gate` 为每个里程碑的默认验证前置（A1/A2 分层语义）；测试命令 `pytest -n 8`（需补 `pytest-xdist` 依赖）。
4. **脚本可移植**：相对路径、`.env` 配置，无绝对路径硬编码。
5. **提交规范**：Conventional Commits；搬运类提交注明来源模块与文件数。
6. **上游维护预算**：每迭代预留 **10~15% 人力**用于上游同步与失效修复。

## 6. 砍需求规则

> 任一条件成立即从本迭代移出至 backlog，**不延期、不降标准**：
> ① 里程碑时间盒到期而任务未完成；
> ② 阻塞外部依赖（Key/代理/消费方排期）在里程碑启动前未解除；
> ③ 该能力无消费方书面需求确认（适用于所有 P1/P2 provider 与冷门子模块）；
> ④ 该能力在验收前已被上游停服或不可达。
>
> 每里程碑结束执行一次，结果记入回顾纪要。

## 8. 已知限制

1. **不支持多 worker 部署**（D8）：本期单进程合一；调度归属由 `ENABLE_SCHEDULER` 显式控制，生产未配置则启动即失败。分布式锁与多进程推送总线为演进项。
2. **Redis 不可用时**：禁用 scheduler + 告警 + 人工介入（不做自动降级，避免多实例裂脑）。
3. 旧 `akshare_data` 库存量表保留只读并行，迭代 1C 执行转移评估后 DROP。
4. 爬虫类接口的可用性依赖上游站点，失效接口按健康标记降级，不承诺永久可用（"失效即弃"）。
5. WS `payload=full` 为实验性能力，大数据集消费方应走 REST 分页或 `opendata_client`。
6. **分钟线不进 MySQL**（D13），走 Parquet 文件 + 元数据索引。
7. 商业源 provider 的交付依赖 Key 到位与消费场景确认，未满足者移出本迭代。
