引用成八进制串而无法解析，清单会静默少一枚而仍印 `findings=0`。本波 94 枚路径现测全部 ASCII
（`git diff --cached --name-only | LC_ALL=C grep -c '[^ -~]'` 读 **0**），所以这一格今天不构成风险；
它留在 argv 里是因为上一条读数来自一枚坏谓词（见本节末「仪器自曝」）。

仪器自曝（本步我写坏两次，都留在记录里而不是抹掉）：

1. 非 ASCII 谓词读假：`grep -v '^[\x20-\x7E]*$'` 在 BSD grep 下把 92 枚路径**全部**报成非 ASCII
   （`\xNN` 不是 BRE 转义）。换成 `LC_ALL=C grep -c '[^ -~]'` 才读出 0。若我照第一版写档，
   本文件会指控自己清单里的 92 枚文件名。
2. 新探针的 `REPO_ROOT` 少数一层 parent：`parents[4]` 指到 `docs/` 而不是仓库根，于是
   `--config docs/.gitleaks.toml` 不存在，gitleaks 以 rc=1 退出且不写报告，而我的 `_scan` 把
   「没有报告」返回成 `[]` —— 臂 B/C 因此各读一条**假的 0 并自称绿**。修法是两处：`parents[5]`，
   加上「无报告 = `None` = 该臂直接 False 并打印 `stderr` 尾部」，再在 `main` 里加一条前提检查
   （`config_exists` 与 `hosts` 任一不成立就 `premise_broken=1 / PASS=False / falsification_exit=1`，
   一臂都不跑）。同一条错误还顺带解释了第 1 格里 `hosts=0`：路径是相对仓库根拼的，根错了整份清单
   就解析不到文件，而旧代码只把它印成一个 0。
3. 第一版反例种的是 40 个相同字符，`findings=0`。原因不在规则正则而在出厂的熵检查：那串字符熵为
   0.0000，远低于 `github-pat` 需要的门。所以第二版把每个体的熵**打印出来**
   （`ghp=4.7255 akia=4.0000 flat40=0.0000`），并把臂 A 的期望写成 `>=1` 而不是我一开始想写的 `==2`。
