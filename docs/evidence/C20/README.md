## 1. 三件事必须分开，否则「接了 ETF 腿」会被读成「有了第二个价格源」

| 环节 | 落在哪 | 谁验的 |
|------|--------|--------|
| 换算键：哪一天、每份派多少 | `endpoints.py::fetch_fund_dividends`（C15） | C15 判据 B/C/E，与新浪逐笔相符 |
| 换算本身 + 通道守卫 | `endpoints.py::unadjust_bars` / `build_fund_etf_prices_request` / `_split_fund_etf_window` / `fetch_fund_etf_bars`（本轮） | 本轮判据 A/B/B′/C/C′/C″/D/D′/D″/G/G′ |

## 2. 通道语义（两次独立实测 + 合计 10,608 格逐格判，非文档转述）

| 事项 | 实测结论 | 落成的代码 |
|------|----------|------------|
| 入参 | 只有 `thscode`（**必须带后缀**，裸码 `code=1002`）、`interval=1d`、`start`/`end`（上海零点毫秒） | `_qualified_fund_symbol` 与分红腿共用同一条规则、同一错误 detail |
| 闭区间 | 上游 `end` 是**含**的：请求侧发 `毫秒(end) - 1` | `build_fund_etf_prices_request`（契约端 `end_date` 仍是闭区间日，适配器 +1 天后右端点 −1ms） |
| `adjust` | **接受但完全无效**：`0/1/2/forward/backward` 与缺省回同一指纹 `2b0488f6991e`，`data.adjust` 恒 `null` | 构造函数**不接受**该参数；适配器层对 `adjust ∉ {"", "unadjusted"}` 在任何请求前抛 `THS_ADJUST_UNSUPPORTED` |
| 单次跨度 | 上限 **1826 天**（1827 起 `code=1003`），而错误文案写「单次不超过 10 年」——那是股票/指数腿的上限 | `FUND_ETF_MAX_SPAN_DAYS = 1826` + `fund_window_span`，守卫文案点名实测值 |
| 可答深度 | 地板 = **今天 − 1827 天**，随探测日滚动（300d 与 1200d 两种窗口下地板同位） | `FUND_ETF_DEPTH_DAYS = 1827`；`today` 显式传入，请求构造函数对时钟保持纯净 |
| 越界怎么报 | `code=0` + **空 `item`** ⇒ 与「这只基金从没交易过」在信封上不可区分（C11a 同一类缺陷） | 发请求**前**拦：`_split_fund_etf_window` 先判地板，`fund_window_depth` 抛出 |
| `limit` | 被忽略（`limit=5` 仍回 196 根）⇒ 不是分页游标 | 不发、也不按它写取数逻辑 |
| 信封戳 | `data.timestamp` 是**窗口内末根**（实测 == 末根 `date_ms`）而不是请求时刻 | 新鲜度判据只能取末根交易日；戳是窗口相对的，拿它当「上游更新到哪天」会静默漏判 |

深度 1827 与跨度 1826 只差一天 ⇒ **「取满深度又取到今天」在一次请求里做不到**，
`fetch_fund_etf_bars` 按 1826 切块；切块不是「分批取全量」（地板之前根本不作答），
只是让取满可答范围成为可能。默认窗口因此是两块（`test_the_default_window_is_the_rolling_depth`）。

## 3. 换算边界「严格之后」是量出来的，不是在两种写法里挑顺眼的

`前复权价 = 不复权价 − 严格晚于该日的每份现金分红之和`。除息日**当天**已经是复权后
的价格，所以边界是「之后」而非「不早于」。这件事不能靠讲道理定，故判据 B′ 要求
**分歧真的被观测到**：

| 基金 | 窗口内除息日 | 除息日上的不等格 | 构成判别 |
|------|--------------|------------------|----------|
| 510300.SH | 3 | 12 | 是 |
| 510050.SH | 2 | 8 | 是 |
| 159915.SZ / 512880.SH | 0 | 0 | 不适用（恒等对照组：两种口径必须逐格一致） |

判据 B 每只基金在 `663 根 × 4 个价格字段 = 2,652 格`上判（四只合计 10,608 格）：
「其后」口径全库只有 **1 格**不等，就是下一节那一格；「不早于」口径恰好在除息日上错。
换算**只动价格、不动量额**，价格在 6 位收口（ETF 最小变动价位 0.001，逐日求和的
浮点噪声在 1e-13 量级）。

## 4. 成交量单位：三条互相独立的证据，谁都不是「照抄 akshare」

akshare 的 `fund_etf_daily` 腿把上游成交量 ×100（东财按「手」计数）。ths 腿若照抄
就整体放大 100 倍，而这类错**不会报错，只会让量能差两个数量级**。三条证据：

1. **C 段** 对新浪逐根相对差：最大 3.58e-08，且「按 8 位有效数字舍入即命中」的格数
   540/640 ⇒ 差异全在**量化**，不是单位。逐位相等在这里不是正确判据，上游的额/量是
   聚合后量化过的值。
2. **C″ 段** 对腾讯：腾讯那一列自己标「手」⇒ 份口径命中 663/663、手口径命中 0/663。
3. **C′ 段 VWAP 自证**（不需要第二个 vendor）：`额/量` 是当天真实成交均价，换算后
   必然落进当日**不复权**高低价区间 ⇒ 四只各自 663/663 命中（合计 2,652/2,652 根）；
   同一格改用**发布价**判只有 168/663（510300）⇒ 这一列同时坐实「量额不参与复权」。

结论：ths 腿**不做任何单位换算**，直接入库，并把「volume in fund units (no x100)」
写进 `Capability.notes`。

## 5. 一格格外的值：三方归因 + 「是不是单格」的收紧判据，不修也不豁免

`159915.SZ 2024-09-30 close`：上游换算后 **2.150**，新浪 **2.232**，腾讯 **2.232**
⇒ G 段抓到 = A（上游单格离群）。G′ 段专门判「离群是不是单格」：落在除息日上、或同
一只基金多天离群，就不是笔误而是系统性口径差。该基金窗口内离群 **1 日 / 663 根**
（1.51e-03），不在除息日上，同日他基金无离群 ⇒ 判为单格。

**离群上限 1 日是跑前写死的收紧，不是为今天的读数留口子**（多于一日即 FAIL）。同
一天新浪的 `volume/amount` 为 0 而腾讯有值 ⇒ 反向归因为**参照侧缺测**（C 段），不算
ths 的错也不算通过。这一格最终登记进 `capability.notes`，既不修也不静默放过。

## 6. 两次跑：冻结跑先立判据，复核跑才判接入

腿接入前后的两次真机跑都留着，且 `diff` 只有该变的地方变：

- 冻结跑 `13:51:20`：判据 F 打印「未接入（本轮先冻结前置测量，接入后重跑即判此项）」；
- 复核跑 `15:58:50`：**除 F 段外逐字节相同**（A/B/B′/C/C′/C″/D/D′/D″/E/G/G′ 全部
  复现，含 1827/1826 两个通道常数、每只 2,652 格（合计 10,608）的判格基数、8 位量化命中数与那一格离群值）。

F 段本轮的读数：注册表路由取回 **664 根**（窗口 `2023-12-29 → 2026-09-24`），逐格对

与合格码 `510300.SH` 取回**同一份 664 根**。两次跑相隔两小时而结论不变，本身就是
「判据不依赖运气」的证据；反过来说，如果 F 段之外的任何一行变了，本轮就得先解释
变化而不是先勾 box。

## 8. 自我更正（都写进代码或输出）

1. **永久对照脚本里有一条「永远不可能为真」的判据**：`judge_leg` 的 `notes_ok` 原写成
   `any(marker in note for note in capability.notes for marker in ("深度", "5 年", ...))` ——
   `capability.notes` 是**字符串**不是列表，于是 `note` 逐**字符**取值，任何多字符 marker
   都不可能命中。这类缺陷的危险在于它只会「一直 FAIL」或（marker 恰好是一个字符时）
   「一直 PASS」，而输出只有一行 `True/False`。改判为对整串 `notes` 匹配实测口径的关键词。
2. **一处 docstring 写了不可能发生的因果**：`unadjust_bars` 的 `fund_unadjust_price` 原写
   「分红大于价格 ⇒ 口径已错」。加法换算只会把价格抬高，这个分支按定义不可达 ⇒ 改为唯一
   可达成因（发布价本身是 0/负数的脏行），并按新文案配用例（`price=0.1` 的 low 落到 0）。
3. **一次「恒等」判据假失败，错在测试助手**：`unadjust_bars(bars, []) == bars` 挂在
   `1.7` vs `1.7000000000000002` —— 是助手自己造出的浮点噪声被 6 位收口抹掉。改助手
   （`round(price ± 0.1, 6)`）而不是放宽判据。
4. **一条既有断言的翻面不是测试写错**：`test_explicit_source_resolves_and_auto_refuses[fund_etf_daily]`
   不再抛 `LookupError`，因为这条腿真的 verified 了 ⇒ 处置是把该域加入
   `_AUTO_ROUTABLE_DOMAINS` 并写明「C20 加入」，**不是**删用例或放宽断言。
5. **`authority_baseline()` 返回元组**：`== ["akshare", "ths"]` 挂 ⇒ 断言写成
   `tuple(baseline) == ("akshare", "ths")`，并额外钉 `baseline[0] != "ths"`（§1 那条反向关系）。
6. **包装脚本的一次口径不一致**：复核跑的抬头由 shell 现场生成，少了冻结跑手写的
   `===== 原始输出（未裁剪） =====` 分隔行。两份日志的**原始输出部分都完整未裁剪**，
   差别只在抬头文案，在此登记以免后轮误读为「输出被裁过」。
7. **一版归因探针因为猜错 dataflow 而得出假结论**：第一版手拼了
   `OECD.SDD.NAD,DSD_LFS@DF_ICP_LFS_UNE`（不是代码里的常量），6/6 拿 404「Could not find
   Dataflow…」——若把它归档，结论就成了「OECD 把失业率序列下线了」，而真实 flow 是
   `unemployment.py` 里的 `OECD.ELS.SAE,DSD_LFS@DF_LFS_INDIC`。已弃用那一版（未归档），
   §11 那份是从注册表取巡检用的**同一个 fetcher、同一份探针参数**重放的。
   教训：证据脚本里凡是拼进请求面的参数，必须来自被检代码的常量，否则量到的是自己的错。
8. **一个数字被撞用成两种量纲**：`2,652` 既是**每只基金**的判格数（663 根 × 4 个价格字段），
   又是四只的**合计根数**（4 × 663），于是「2652 格逐格判」这句在代码 docstring、映射表与
   对照表里同时读得出两种意思。已核实的口径是：**合计 10,608 格**（每只 2,652 格）、
   **合计 2,652 根**（每只 663 根）。已把 `fund_etf_daily.py` / `registration.py` /
   `endpoints.py` / `endpoint_map.yaml` / `openbb_map.yaml` 里指「判格总数」的那几处统一改写
   为 10,608（并保留每只 2,652 的分解），指根数的地方写明「四只各 663 根、合计 2,652 根」。
   两份原始对照日志不改（它们是未裁剪输出，且表头 `663 | 2652` 的列义本来就写清了）。
9. **一条实测结论先只落在本轮 README，没落进代码**：ETF 信封 `data.timestamp` 是**窗口内
   末根**而不是请求时刻 ⇒ 新鲜度判据只能取末根交易日。这条最初只在 §2 的表格里，而
   `opendata_fuyao/endpoints.py` 的端点语义清单已经为成分股（那个才是**请求时刻**）与财务
   报表（最新报告期末）各立了一条 bullet ⇒ 补成第三条（README 里的一条实测对下一个改这段
   代码的人不构成约束）。同一轮**不**改 `capability.notes`：归档的对照日志原样打印了那串
   notes，事后改写会让日志与代码对不上。
10. **归档日志的抬头被 shell 的引号规则改写过**：写第二次门禁跑的包装命令用了双引号串，
    里面的 `` `endpoints.py` `` 一类反引号被 shell 当成命令替换执行，于是抬头三行里的文件名
    全部消失（stderr 上留下 `command not found: endpoints.py` 等 6 行），末尾还多打了一遍
    `===== gate: PASSED =====`。**门禁本身不受影响**（`GATE_EXIT=0` 读自文件内部，判定面
    读数与第一次逐项相等），但归档件的说明性抬头已不可读 ⇒ 只修框架行（抬头 3 行改写、
    多出的标记行删除），`===== 原始输出（未裁剪） =====` 与 `===== 原始输出结束 =====` 之间
    的字节一字未动，改法与改后读数见 `gate-run-comparison.txt`。教训：往 shell 字符串里写
    含反引号的中文文案，必须用单引号或 heredoc。
