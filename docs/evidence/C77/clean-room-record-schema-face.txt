## What was found

AC-16|01 is 「每个自研 provider 有**审查留档**」 and AC-16|02 is 「全库无 OpenBB 源码或其近似复制」.
Both judges read the 留档 half through `record_bodies()` + `legacy_prose_record_face()`: any line
anywhere under `docs/evidence/**` that contained the phrase 「无 OpenBB 源码参照」 and matched a
package name by `\b<name>\b` was counted as that package's review record.

Measured on this tree, that leg credits **7 packages over 8 lines**, and every one of those lines is
one of two things:

- `docs/evidence/C64/remaining-items-audit.md:205,207` — text of the form
  「提交说明带「无 OpenBB 源码参照」的 0 个」, i.e. a sentence stating that the record **does not exist**;
- two `docs/evidence/C65/item-readings-*.{json,txt}` dumps of this very probe's own reading.

Neither carries a `PROBE_ECHO_MARKERS` string on its face, so the marker filter in `record_bodies()`
let both through. The judge therefore green-lit an item because a round had printed the word "gap"
near a package name. That is the finding: **the 留档 half of two items was measuring its own output**.

## What the tightening does

`canonical_clean_room_records()` replaces the prose grep with a schema face:

- one **tracked** file per package at `docs/evidence/clean-room/<package>.md` (path-gated; the same
  conforming text filed anywhere else is refused — arm `wrong-path`);
- `审查日期` ISO, `审查人` non-self-referential, `方法与反证` written out;
- `覆盖面` equal to that package's measured `.py` census, and `代码面摘要` equal to the sha256 of
  those exact bytes (`路径\0字节\0` per file), so a record stops being credited the moment the code it
  reviewed moves — arms `stale-census`, `digest-drift`, `bytes-moved`;
- a conclusion line carrying 「审查结论」 + the package name + the phrase, **and no negation token**,
  so 「无法证明 akshare 无 OpenBB 源码参照」 is read as a disclosure and refused — arm
  `negated-conclusion`;
- probe-echo markers still refuse the whole file, now as an explicit arm (`echo-mark`) rather than an
  implicit hope.

Every refusal is a printed reason, one line per package. The old face's second failure was silence:
the reading said "7 packages" and nothing said what those 7 were made of.

`legacy_prose_record_face()` stays in the file and is still **measured and printed** as a contrast
(`旧口径…会记 7 个包 / 8 行`), but it is in no judge. Three new breaks ride on the new fact
`record_refusals` for AC-16|01 and one for AC-16|02, and both repairs now have to drive it to `0`.

One incidental defect the fixture caught: `provider_py_digest` was `@lru_cache`d on the file *names*.
Within one process that hands back the digest of bytes read earlier, so the `bytes-moved` arm would
have certified a stale review — exactly the face that must be a fresh reading of disk. The cache is
gone; the cost is nil next to the AST walk the same item performs (AC-16|02 parses 649 runtime files
in about 1.5 s wall, measured in the same invocation as the item reading archived below).

## Scope of the claim, measured

The live arm prints `recorded_pkgs: 0 / record_refusals: 12` with 12 verbatim reasons, all of shape
「没有逐包档案（docs/evidence/clean-room/<pkg>.md 未跟踪）」. **This round wrote none of those records,
and it is not the instrument's fault**: the honest reading of AC-16|01/02 after C77 is `gap`, and the
retraction of the previous "proven-shaped" 7/8 is the point of this file.

What this round does **not** claim:

- It does not claim the 12 packages are clean-room. The affirmative arm credits a *fixture* package in
  a temp git repo; nothing in this file is an attestation about `akshare`, `sec`, `fmp`, `bls`,
  `cboe`, `federal_reserve`, or the rest.
- It does not claim `AC-16|02`'s 「近似复制」 half is decided. The AST walk measures 0 `openbb` import
  roots over 649/649 runtime files with 98 distinct import roots read (so the walk is not spinning),

  half. The judge keeps it red for that reason.
- The 7/8 provenance trace was read off `docs/evidence/**` by this probe; re-derive the lines with
  `grep -rn "无 OpenBB 源码参照" docs/evidence | head -40`.
