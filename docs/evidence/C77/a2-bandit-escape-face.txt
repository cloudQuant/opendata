## What was found

`a2_check._bandit` ran bandit with `-f json -q` and parsed **`stdout + stderr` as one string**.
bandit writes its `nosec` bookkeeping warnings ("Test in comment: argv is not a test name or id,
ignoring", "nosec encountered (B603), but no failed test") to **stderr**, and this repo's A2 set
emits them — the live arm measures 7,540 stderr bytes against 761 stdout bytes for one file. So the
combined string is not valid JSON, `json.loads` raised, and the handler's
`except JSONDecodeError: return True` branch answered **"pass"**.

That is the shape of the finding: an approval produced by *not reading* the tool output.

## Scope, measured rather than argued

The shaped arm forces a finding into stdout with the exit code pinned to 0. That state is **not
reachable under this repo's config today**: `bandit.yaml` (1,200 bytes) carries neither `exit_zero`
nor `level_severity`, so bandit exits non-zero when it reports, and the old `code != 0` guard
already returned a failure. The probe prints that reading instead of asserting it
(`shaped_state_reachable_today: False`).

So the honest verdict on run 5 is: **the bandit leg's answer was correct-but-unread, and it was a
latent fail-open** — one config knob away from passing real findings. It was *not* an observed
mis-verdict, and this file does not claim it was. Two of my own earlier readings did, and they are
retracted below.
