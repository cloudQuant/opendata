# AC2-18/19 离线实施决策

2026-10-12，主代理制定。此文件定义实施边界，不是验收收据。

## 财务版本

保留现有最新值 DWD，新增版本与冲突表，不原地改变旧表主键或重写旧值。版本必须同时保留来源、财务业务键、来源版次、公开时间及精度、观察时间、来源依据和内容摘要。重复同版同内容幂等；同版不同内容必须保留冲突并拒绝在 PIT 视图中任选一条。更晚版次不可覆写较早版本。

提供明确的版本存储服务及实际 API/SDK 的 as_of 读取链。公开时点与观察时点独立；fetched_at、合并窗口末日和 _as_of trace stamp 都不充当公告事实。仅有日期时保留来源时区与 date 精度，timestamp 查询采用该来源日期结束后的保守可见边界，不能把全天未知公告当作当天零点已知。合法 date 查询语义与 timestamp 查询精度须文档化。

历史来源覆盖必须显式声明。THS 等只有当前快照且不能证明旧版发布时间的行，可保存观察及冲突，但不得作为公开历史版本查询成功；明确返回 PIT_UNSUPPORTED 或覆盖不足。现有 DWD 写入点与新版本服务连接，支持正式来源事实的入口需显式传入经核实的元数据，不能用默认 revision=1 自动断言没有重述。原始历史数据回填仅生成待复核档案，不自动赋予历史可见性。

迁移在 alembic_data 的 0007 后新增 0008_financial_pit；本轮只开发及离线 SQLite/DDL 验证，不运行仓库数据库迁移。旧 DWD 普通读取保留；PIT 读取必须确认新表存在和覆盖。新增表的回退不破坏旧 DWD；实际降级删除历史前仍需正常备份治理。

验收至少包括两次公开发布、同一财务键重述、公告前后、日期精度/时区边界、重复重放、同版冲突、晚到数据、来源与证券隔离、缺少可证发布时间、SQL 参数绑定和 API/SDK 透传。由另一个验收代理重做正例和 counterfact。

## 公司行为

新增独立事件版本及冲突存储，保留旧 stock_action DWD 和已有不明确同日事件拒绝行为。源 event_id 或来源可证、经审阅的稳定复合业务键可成为事件身份；payload SHA 只能作内容/重放摘要，不能自动作经济事件身份。行号和抓取时刻均不得分裂事件。

只有明确共同的除权前每股基准，才允许同日现金、送股和配股分项合并计算：现金与份额分别求和，配股认购金额按份额乘价格求和，再由总份额计算等价价格。若来源指明顺序换股，必须有明确次序和基准；否则保留冲突并拒绝。多个来源镜像同一事件不能重复计入。更正版本替换该事件在当前计算中的旧版，同时保留历史版本及受影响日期集合。

先实现可审核身份/基准的显式准入、持久冲突、确定性因子输入和受影响 key 传播；不得将现有 THS payload digest 无条件提升为经过证明的业务键。合成 gold 只验证算法，实际来源 gold 尚缺则该来源回填与正式 AC2-18 保持 INCOMPLETE。迁移新增 0009_corporate_event_versions 接在 0008 后，避免产生多头；不执行真实数据库迁移。

公司行为 worker 不改财务 writer/API 路径；两个 worker 的共享挂钩由主代理另行合并。中央 domains/models 导出仍由 integration 唯一维护。
