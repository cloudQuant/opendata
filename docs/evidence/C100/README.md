# C100：32 来源全量实现与独立验收推进

日期：2026-10-12（Asia/Shanghai）。状态：**开发进行中，未完成验收**。

本轮承接当前工作树，固定目标为 32 个 OpenBB 来源、350 个 provider×model 身份，加 AkShare/THS 两个自有来源。OpenBB 只用于名称与输出契约对照；新增取数、解析和转换实现依据来源自身的公开资料。当前注册数、离线测试数和固定模型完成数分别记录，互不替代。

## 并行开发边界

来源工作者拥有各自 provider 目录、明确分配的具名契约文件、来源专属测试以及本目录下各自证据子目录。公共 `catalog.py`、`models/__init__.py` 和 `domains.yaml` 由单一 integration 工作者接线。不得覆盖未分配的既存改动。

`integration.json` 是工作者之间的交接资料，**不增加运行时注册机制**。运行时仍使用现有 Provider 的 LazyFetcherBinding、中央目录与域语义登记。来源工作者必须把真实实现绑定进自己的 provider.py；中央整合只在实现自测完成后进行。

“固定 CSV”指迭代2的 `模型级任务清单.csv` 身份集合，不限制上游响应的文件格式。JSON、XML、HTML、ZIP、CSV、工作簿与文本表按来源事实分别解析。不得用六份数据文件替代六个不同模型身份。

## 本轮判定要求

- 实现须有真实取数路径、严格类型输出、参数前置校验、来源时间/单位/业务键语义，以及适用的分页和配额边界。
- 各来源可复算的正例和 counterfact 反例必须使用独立手写的来源形状样本；不能让被测转换函数同时生成期望结果。
- 自测后另派未实施该切片的验收代理，检查真实注册/服务路径，并保存执行命令、代码和样本 SHA256、退出码、逐项观测与限制。
- 来源权限、网络不可达和文档缺失保持明确状态；不注册空壳，不把合同类型或静态 manifest 算成实现。
- 独立验收通过之前，不把自测、历史探针或口头结论写成逐条验收完成。live 来源、生产部署与离线实现保持分轴。

`baseline.json` 是并行派发后、中央整合前的工作树观测，不冒称初始时刻或冻结验收快照。未提交补丁保存在本机临时恢复文件中；本轮没有提交或推送授权。

用户在本轮明确：TMX、BizToc、Stockgrid、WSJ、Seeking Alpha 的额外接口资料与样本暂时没有，先继续实现，后续验收时再由用户补齐。因此这些外部材料不阻断其他开发任务，也不因延后提供而转为已验收；见[后续验收补齐清单.md](后续验收补齐清单.md)。

对于 CFTC、EIA、IMF、OECD 的新增 21 个绑定，用户随后明确「用途后续再补，保持未确认」。[用途候选表](新增模型用途待确认.md)只保留草案；不写成批准场景，AC2-08 继续保留对应缺口。
