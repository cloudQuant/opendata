===== findings =====
1. Clean tree: 74 routes parsed, 13 fixture stubs parsed, and all three counters at
   zero — every URL the e2e plane answers is a URL the app serves, wrapped the way the
   handler wraps it, matched by its own literal path rather than by a parameter.
2. /api/v1/tables/{table_id}/schema is the only bare (non-enveloped) handler the plane
   stubs, and its fixture declares itself BARE — the pairing agrees. 14 handlers return
   bare objects in total; the other 13 (settings/database x3, keys x3, users x3,
   data capabilities/sources/download/download-status) are on pages the e2e plane does
   not visit, so no fixture asserts an envelope about them in either direction.
3. Item keys are read through the serializer, not guessed: /scripts/ and /tasks/ via
   _script_to_dict()/ScheduledTask.to_dict(), /executions/ via TaskExecution.to_dict(),
   /tables/ via TableResponse.model_validate(...).model_dump(), /pipeline/failures from
   an inline dict literal. Before this round the last two were reported as no item keys
   at all, silently, because the list was a name ("items": items) rather than an inline
   comprehension.
4. /api/v1/executions/stats resolves to opendata/services/execution_service.py:207 —
   the handler and the service method share the name get_execution_stats, which is why
   the resolution stack is keyed by (file, name): keying it on the bare name refused the
   hop and printed no keys for that route.
5. TaskExecution.to_dict() carries 14 keys and rows_processed is not one of them
   (id, execution_id, task_id, script_id, status, start_time, end_time, duration,
   rows_before, rows_after, error_message, retry_count, triggered_by, created_at). The
   e2e fixture therefore reads rows_before/rows_after, which is the C32 D1 note.
6. GET /api/v1/tables/3201/data: data.rows is a list of database rows keyed by whatever
   columns the table has, so the census prints "element shape this census cannot read"
   instead of inventing a key list. That one entry is the only shape in the plane it
   does not resolve.

===== limitations, stated rather than left to the reader =====
* This is a static reading of source. It measures the shape a running server emits for
  the handler as written; it cannot say a value is right, and it never starts the app.
* It cannot see envelope-insensitivity at the browser layer: the axios interceptor
  accepts both {success,message,data} and a bare object, so no fixture or assertion at
  that layer distinguishes one envelope from two. docs/evidence/C32/falsification.txt
  case E is the measurement of that claim, and it stayed green under mutation.
* A URL whose segments are all path parameters (e.g. /api/v1/data/{asset_class}/{domain})
  is a route FastAPI genuinely answers, so such a stub pairs instead of orphaning; only
  the STUB-TYPO rule (a real route one or two characters away at that segment) catches a
  key that was meant to name a literal endpoint and misspelled it.
