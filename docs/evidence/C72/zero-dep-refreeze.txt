3. Second, deeper failure the re-freeze path exposed
--------------------------------------------------------------------------------

    python scripts/codemod/verify_no_akshare.py --update
    FAIL: refusing to freeze an unusable reference policy: stale sha256: opendata/data/providers/catalog.py
    UPDATE_EXIT=1

`--update` rewrites the *baseline* only; the reference policy (`docs/quality/akshare-reference-allowlist.json`)
pins a per-file sha256 for every path allowed to contain an `akshare` reference, and `catalog.py` had been
rewritten after C66 pinned it (C72 changed registration to be derived). The scanner treats ANY hash drift as
a problem unconditionally (`verify_no_akshare.py:600-603`), which is correct: a hash pin is the only tamper
evidence that the reviewed content is still the reviewed content.

A hash refresh would be the wrong repair if the allowance's *substance* had changed — a file that grew a new
reference needs a review, not a digest bump. So the drift was audited against the pinned content, by locating
the revision whose bytes hash to the pin and comparing the akshare-bearing lines:

    pinned sha256  c2467502db2c6dc5df9418d89f06b46dd77ac2f10785a9c932396f964a35ff85
    matches        opendata/data/providers/catalog.py at 3f05f636 (C66) — 1 of 3 revisions touching it
    live  sha256   10dcfe1420952a34a89ad2369852a9e268f8d5db5c40fe745f03708b67fbc0ef

    occurrence lines @ 3f05f63            occurrence lines @ HEAD
    :13 import PROVIDER as AKSHARE_PROVIDER   :13 identical text
    :86 AKSHARE_PROVIDER,                     :88 identical text
    :92 AKSHARE_PROVIDER,                     :94 identical text
    count=3                                   count=3

Same three lines, same kinds, only the line numbers moved (86→88, 92→94) because C72's derived registration
inserted two lines above them. The registered `purpose` ("统一目录把搬运后的 akshare provider 作为来源标识注册
进 provider×模型目录，import 的是 `opendata.data.providers.akshare.provider` 的模块路径。") still describes the
file. The pin was therefore re-audited, not merely re-pointed, and the entry's `reviewer`/`reviewed_date`
carry the audit instead of silently advancing.
