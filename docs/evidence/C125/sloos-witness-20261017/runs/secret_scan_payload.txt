## 1. 为什么是两臂

shipped 配置第 180 行有一条全局 `[[allowlists]]`（line-targeted，正则
`"[^"\n]{2,160}?/[^"\n]{1,160}?\.[A-Za-z0-9]{1,6}": "[0-9a-f]{64}"`），它豁免的正是
"路径 → 64 位十六进制"这一形状，而本波 1348 枚改动里绝大多数就是这个形状。
只用 shipped 臂读出的 0 无法区分"没有凭证"和"凭证被这条豁免吃掉"，所以第二臂换成
只留 `[extend] useDefault = true` 的 bare 配置（仓库级 allowlist 整条拿掉）。
两臂同为 0，才把 0 记成判定。

## 2. 对照臂：这台仪器必须能不为零

先记两条**假控制**（它们的 0 是控制写错了形，不是扫描器没跑）：

```
DEAD_CONTROL_1  AWS 文档示例值 AKIA…EXAMPLE + wJalrXUtnFEMI/…EXAMPLEKEY -> 0 findings
                （gitleaks 默认规则把文档示例值本身列了豁免）
DEAD_CONTROL_2  ghp_ + 40 个字符                                        -> 0 findings
                （github-pat 的 body 定长 36，超长的串落不进规则）
```

LIVE_CONTROL 的 body 必须在运行时生成、不入库（36 位 `[0-9A-Za-z]`）：

```bash
BODY=$(/Users/yunjinqi/opt/anaconda3/envs/py313/bin/python -c \
  "import secrets,string;print(''.join(secrets.choice(string.ascii_letters+string.digits) for _ in range(36)))")
mkdir -p /tmp/ctlrepo/sub && cd /tmp/ctlrepo && git init -q .
printf 'GITHUB_TOKEN = "ghp_%s"\n' "$BODY" > sub/planted_ghp.py
git add -A && git -c user.email=t@t -c user.name=t commit -qm control
```

三种跑法都要报同一枚 `github-pat`：

```
throwaway git repo, git 模式,      shipped 配置 -> findings=1 ruleId=github-pat file=sub/planted_ghp.py
同一 repo,          --no-git 模式, shipped 配置 -> findings=1 ['github-pat']
同一 repo,          --no-git 模式, bare 配置    -> findings=1 ['github-pat']
```

最贴提交面的一臂（IN_PAYLOAD_CONTROL）：把这枚 token 直接种进**载荷副本里**再扫，计数与分母同时动，
看完删掉：

## 3. 取数配方（可重跑）

```bash

    --report-path /tmp/round.json 2>/tmp/round.log
  echo "cfg=$cfg exit=$? findings=$(/Users/yunjinqi/opt/anaconda3/envs/py313/bin/python -c \
    "import json;print(len(json.load(open('/tmp/round.json'))))") $(grep -oE 'scanned ~[0-9]+' /tmp/round.log | tail -1)"

# 对照臂：把 §2 生成的 token 种进副本、扫、删
printf 'FRED_API_KEY = "ghp_%s"\n' "$BODY" > /tmp/c125_scan/docs/evidence/C125/planted_probe.py

  --report-path /tmp/planted.json    # -> findings=1
```

## 4. 本波真正的一条 finding：我的载体自己中招

提供方（provider fixtures）与证据 JSON 一条没报，报的是我自己写的说明文。
处理：本文件重写为运行时生成 token 的配方（§2/§3），不保留字面量；重写后重扫的两轮读数记在 §6。

这是 C119 那条"引用传播"的老账再犯一次：把被判定的行原样抄进载体，载体就成了下一个被判定的行。
凭证面尤其致命 —— 它没有"这只是文档里的示例"这种豁免可用，加了豁免就等于把真 token 也放过去。

## 5. 载体命名面的一条缺陷

`probes/resign_all_pins.sh` 把逐家日志写成 `/tmp/resign_$p.log`，我拷进档案时沿用了 `.log` 名，
而 `.gitignore:61` 是全局 `*.log` —— 这两枚试签日志在 `git status` 里根本不出现，
等于 face.md §1 的写集表列了两枚提交不进去的载体。已改名 `runs/resign_{finra,multpl}.txt`。
同一条也解释了为什么 §3 的分母要用 `git ls-files --others --exclude-standard` 而不是 `find`：
后者会把被忽略的文件也算进来。
