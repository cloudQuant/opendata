--- 3. 值就是被命名文件的 sha256（正面证据，非“看起来像”）---
对每条命中的 (键路径, 值) 重算 sha256(该文件字节)：
  相等=364   不等=49   命名文件已不存在=27
不等/缺失是档案快照的应有之义：清单写下之后源码继续演进、部分路径后来改名或迁移
（C64/C65 的本轮快照对应 166 条 pin 漂移，另见 ac2-findings.md F2）。
一条真凭证不会以“某个仓库文件路径的 sha256”的形态出现，也不会随源码演进对不上。
复算片段（read-only）：
  python3 - <<'PY'
  import hashlib, json, pathlib, subprocess
  REPO = pathlib.Path(".")
  d = json.loads(pathlib.Path("leaks.json").read_text())   # gitleaks -f json -r leaks.json
  key = lambda m: (m.group(1), m.group(2))
  hit = miss = absent = 0
  for f in d:
      rel, ln = f["Fingerprint"].split(":")[1], int(f["Fingerprint"].split(":")[3])
      line = (REPO / rel).read_text(errors="replace").splitlines()[ln - 1]
      import re
      m = re.search(r'"([^"\n]*?/[^"\n]*?\.[A-Za-z0-9]{1,6})": "([0-9a-f]{64})"', line)
      if not m: continue
      name, digest = m.group(1), m.group(2)
      blob = (REPO / name).read_bytes() if (REPO / name).is_file() else \
          subprocess.run(["git", "show", f"{f['Commit']}:{name}"], capture_output=True).stdout or None
      if not blob: absent += 1
      elif hashlib.sha256(blob).hexdigest() == digest: hit += 1
      else: miss += 1
  print(hit, miss, absent)
  PY

--- 5. 处置：允许面按形状收口，不按路径收口（含一次被推翻的写法）---
先写成的版本是 `[[allowlists]] paths=['''^docs/evidence/'''] + regexTarget="line" + 形状`，
注释里把它说成“路径与形状两个条件同时成立”。这个说法是错的，并且是被实测推翻的：
在一次性 git 仓库里（一个提交内同时放摘要对与一枚 ghp_ 令牌），
带 paths 的配置把**那枚真令牌也一起吞掉了**（探针仓库读数见 log §[6]：paths 版命中为空，
被吞掉的集合含 leaky.py:1 与 config.json:2），
因为 gitleaks 对允许面的各条件是**或**关系，不是且；`paths` 单独成立即可放行。
这正是本配置抬头记载过的那次事故（宽 `^docs/` 允许面吞掉 docs/evidence 里的真令牌）。
所以 `paths` 已删除，允许面只按形状收口：
  "[^"\n]{2,160}?/[^"\n]{1,160}?\.[A-Za-z0-9]{1,6}": "[0-9a-f]{64}"
另注：`--no-git`（工作区扫描）下文件路径是绝对路径，`paths` 连字面都不匹配，
两条语义不同的面不能混用——这也是探针改在 history 模式跑的原因。

再一处装置缺陷（同一轮内改掉）：探针最初**手抄**了一份被测正则，抄成 `[^"\n]*/…`（键名段
没有长度下限），与落库配置里的 `[^"\n]{2,160}?/…` 并不相同。也就是说 §[1] 的“441/441 全在
摘要行上”一度是用**比真允许面更宽的分类器**算出来的——这正是要防的那种自证。现已改为用
tomllib 从 `.gitleaks.toml` 解析 regexTarget=line 的那条 64-hex 允许面，手抄面消失，
log §[0] 把被测形状本身打出来；用权威形状重跑，§[1] 读数不变（offenders=0、吞掉=441）。
对照组也从 HEAD 改成钉死 `CONTROL_REF=5a23239`：允许面落库之后 HEAD 就越过对照了，
不钉死的话每一轮复跑都会“没有对照组”而静默变成一条只证自己的臂。
