### F. 主腿字段面（3 只标的逐信封）

信封出现过的键并集 = `ticker` / `ex_date_ms` / `dividend_per_share` / `per_share_bonus`。
被量的 600030 那次配股（`2022-01-27`，`dividend_per_share=0`、`per_share_bonus=0`）**没有带任何配股列**。
ths 腿模块文档原先写着「the allotment columns map onto the rights fields」——那两列在本 leg 的
normalizer 里从没被读过，文档描述的是一个不存在的映射，本轮按实测改成「量到的回包没有这两列 +
单位从未量过 ⇒ 留契约默认值，不猜」。注意收窄的边界：`allotment_ratio`/`allotment_price`
**确实存在于上游词表**（`alembic_data/versions/20260923-0003_ods_ths.py:60` 的 ODS 建表、
`opendata_fuyao/dumps.py:380` 的 dump 读取都带这两列），所以这不是「上游永不发」，而是
「live 侧一次都没给过、且没人量过它的单位」——差别见 §10 第 2 条。

## 3. 这个单位错为什么能穿着绿测试活到现在

`tests/test_p0_providers.py` 里原有一条 `test_maps_rights_plan_ratio`，夹具是**手写**的：

- `配股方案 = "10配3"`（str），而 live 页面被 `pd.to_numeric` 强转成 **float64**（`1.5`）⇒
  生产 `_parse_rights_plan` 对非 str 直接 `return 0.0`，真实数据上比例恒 0；
- 同一个夹具把 `配股价格` 的期望写成 ÷10 后的值 ⇒ **测试把 bug 写成了判据**。

⇒ 夹具与上游形状不一致时，绿套件与坏适配层可以同时成立。本轮的处理不是删断言，
而是换掉事实来源：夹具逐格抄真机读数（`fixture-live-cells.txt` 把列名、dtype、
每个单元格的 **Python 类型** 都打出来），再把一条含糊的断言拆成**两条各自可独立证伪**的
（比例对上 `10配1.5`、价格对上 `14.43`），另加一条 `"10配N"` 文本写法的向前兼容用例。

## 4. 机制：可见化，判定面一个字不动

- **分级**：带经济内容的无日期行 ⇒ `logger.warning`（数量 + 前 3 条样本 + 为什么可能是缺口）；
  契约要求的窗口裁剪 / 全零行 ⇒ `logger.debug` 计数。理由是 C26 量到的两类比例：118 行 vs 5 行，
  把例行丢弃也上 WARNING 就会把真正的 5 条淹掉（D4 变异用例守着这条）。
- **`Capability.notes` 写口径**：601318 `1.0` vs `1.2` 的具体差额 + 「比例是名义每 10 股、不是实际缴款额」，
  让 `/sources` 的读者不用翻代码就知道这条腿会少给什么。`verified` 保持 **false**。
- **为什么走日志而不是返回值**：`FetchResult` 是 `Sequence[ContractModel] | pd.DataFrame`，
  没有元数据通道；加一个就要动所有 provider 的契约，而本轮要的只是「少给的行要说出来」。
- **不动路由**：本轮没碰 `patrol.py`/registry。`live-patrol.txt` 复跑 20 条 verified 腿全 `[ok]`、
  `失败 0 项；抖动 0 项；字段级偏差 0 项（未判读 0 项）；必配 Key 缺失 1 项`、`PATROL_EXIT=0`；
  `ths/instrument` 探针 `5578 rows, 1485ms`（C25 为 2391ms），四行 canary 形态与 C25 逐项相同
  （`a-share/list_date` 缺 8/5578 满值、`a-share/name` 0、`a-share-index/list_date` 0/1431、`futures/list_date` 265/1142 partial）。

## 5. 明确拒绝的两种「修法」

1. **拿公告日期给预案行补一个除息日**。上游没给日期就是没有日期，把 `2018-04-27` 当成除息日会造出
   一个 fuyao 都不认的事件日；而且 601318 的差额 0.2 恰恰属于**已有日期**的 `2018-06-07`，
   补日期反而把它挪错地方。D5 变异用例（把丢弃分支换成 `ex_date = as_date(公告日期)`）必须变红。
2. **在主腿 normalizer 里「读出」配股**。量到的行里没有这两列、单位没测过，
   凭 sina 的每 10 股口径去猜一个未知单位的列，是把 10 倍误差搬进复权因子公式
   （`opendata/pipeline/factors.py:82` 直接用 `allotment_ratio` 做分母）。D6 守着这条。

## 7. 过程中被推翻的四处设计（不遮掩）

1. **度量脚本自己复算了单位换算**。首版 C/E 两节在脚本里调生产 helper（`_parse_rights_plan` /
   `_per_share`）重算「适配层现值」，于是 ÷10 修完之后脚本照样打印 `rights_price=1.443` 和
   「适配层与 em 口径不符 6 条」。一个自己复算判据的脚本会永远停在旧结论上。
   修法=C/E 改为直接读 `transform_data` 返回的 `CorporateAction` 行。
   基线档为什么仍可信（已写进新档抬头）：修复前生产代码走的正是那两个 helper，
   复算与实发逐字相同；两份档案的真实差异只有窗口，已在抬头里点名。
2. **配股查询沿用了探针窗口**。抽样里 6 个有除权日的配股事件有 5 个早于 2015，
   按 `2015-01-01..2024-12-31` 裁完就只剩 1 条可读，单位问题直接没得量（基线档 C 节里
   「适配层返回 0 条」的四行正是这个原因，那些「现值」是复算而非发布）。
   本轮为 C 节另开全史窗口 `_rights_query`，并在抬头声明这一处与基线不可比。
3. **预检首跑什么都没跑就差点算数**。原写法只判 pytest 退出码非 0，而 node id 写错时
   退出码也是非 0——「用例名不存在」会被读成「变异被抓到」。加预检后首跑立即以 1 中止
   （那份记录留在 `mutation-proof-preflight-abort.txt`），并进一步要求报告里出现 `1 failed`；
   期间还发现 D6 的类名写错（`TestVocabularyNormalization` → 实际是 `TestNormalizers`），
   这条如果不被预检拦住，整份 mutation-proof 就是假的。
4. **「本轮改动都有用例」这句自我判断被门禁覆盖率表否掉两次**。第二跑 `GATE_EXIT=0`，
   但同一份日志里 `stock_action.py` 是 `83.62%  144-148, 150-151, 153-154`——配股页那三类
   丢弃一条用例都没有，而 ÷10 这个 bug 正是藏在「配股分支没有用例」这个形状里活的；
   第三跑剩 `122->124, 144->148`，即分级判据只钉住了「该说时要说」，没钉「不该说时别乱说」。
   两次都是补具名用例 + 补第 7 段变异（D7），而不是把「覆盖率有缺口」解释成不计分。
   前两份绿跑各留一档并在档尾写明它为什么被替换（见 §6 表最后两行）。

被否掉的三个交叉校验面：sina 配股**详情页**（本轮现场看过，整列都是 `--` 占位，**未单独归档**）、
`募集资金合计`（600030 该格为 `NaN`，见 `fixture-live-cells.txt` 的 dtype 行）、`除权参考价`
（是残差，反推不出比例）。东方财富通道在度量过程中失败过一次（响应被截断），
按「量不到 ≠ 数据错」记为未判读并另存补跑档（§9 第 4 条）。
