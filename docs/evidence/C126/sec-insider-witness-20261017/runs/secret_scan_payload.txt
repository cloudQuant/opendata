## 1. 两臂，以及本波为什么 bare 臂不承重

shipped `.gitleaks.toml` 只有一条 `[[allowlists]]`（`regexTarget = "line"`，正则
`"[^"\n]{2,160}?/[^"\n]{1,160}?\.[A-Za-z0-9]{1,6}": "[0-9a-f]{64}"`），豁免的是"同一行里
`路径 → 64 位十六进制`"这一形状。C125 §1 的理由句在本波被普查否证：

```
docs/evidence/C101 全树  files=4671  含引号 64hex 的行=259828  命中豁免正则的行=0
本波载荷 167 枚          行=214351                              命中豁免正则的行=0
```

命中 0 的原因在产物的写法里：producer 用 `json.dumps(..., indent=2)` 一键一行，
摘要写成 `"after_sha256": "<64hex>",` 与 `"path": "opendata/data/models/sec_iter2.py"` 两行，
路径与摘要不同行，那条 line-targeted 正则结构上抓不到本仓的证据 JSON。
所以本波两臂同为 0 **不是**"豁免吃掉了凭证"，也不是"bare 臂多做了一次功"—— 它在这些字节上无差别。

但豁免不是没有能力，能力用一份合成人测过（`.w21-scratch/w21_diff_arm.sh`，token 由运行时生成、
脚本用后即删）：把一枚 `ghp_`+36 写在一条**真的豁免形状行**里，与写在**自己一行**，两臂读数不同：

| 版面 | shipped 臂 | bare 臂 |
| --- | --- | --- |
| token 与 `"路径": "<64hex>"` 同一行 | exit=0 findings=0 [] | exit=1 findings=1 ['github-pat'] |
| token 单独一行（pair 仍在文件里） | exit=1 findings=1 ['github-pat'] | exit=1 findings=1 ['github-pat'] |

即：这条豁免能在"凭证与摘要对同行"时把真凭证吃掉（`regexTarget = "line"` 的固有后果，
`.gitleaks.toml` 170-178 行的注释也是这么写的）；本波载荷里这种同行行数为 0，所以第二臂是保险，
不是本波的判据。把这句写成判据而不是沿用 C125 的理由句，是本波凭证面真正落下的东西。

## 2. 对照臂：这台仪器必须能不为零

```
DEAD_CONTROL_1  AWS 文档示例值 AKIAIOSFODNN7EXAMPLE + wJalrXUtnFEMI/…EXAMPLEKEY -> exit=0 findings=0
                （默认规则把文档示例值本身列了豁免；本波重测仍为 0）
```

**C125 记的第二条假控制是错的，这里更正**：C125 §2 写「`ghp_` + 40 个字符 → 0 findings，
因为 github-pat 的 body 定长 36，超长的串落不进规则」。本波把同一条臂重跑，读数是 **2**：

```
ghp_ + 40 位全数字      -> exit=1 findings=2 ['generic-api-key', 'github-pat']   （shipped 与 bare 同读数）
```

长度普查（body 为随机 `[A-Za-z0-9]`，shipped 配置）给出真实边界：

```
len=30 -> 1 ['generic-api-key']
len=35 -> 1 ['generic-api-key']
len=36 -> 1 ['github-pat']            ← 只有专规则，generic-api-key 反而不出
len=37 -> 2 ['generic-api-key', 'github-pat']
len=40 -> 2 ['generic-api-key', 'github-pat']
```

所以 `github-pat` 不是"定长落不进"，而是无前缀锚定的 `ghp_[0-9A-Za-z]{36}` —— 40 位的串里
含一段可匹配的 36 位前缀，规则照样报。C125 那次 0 的读数我按自己的配方无法复现（长度 40、
字符集不记），保留原记录并在 §83 的更正表里公开。教训的形状与 C125 §4 同源：
**登记的"假控制"本身也得是一条读数，不能是一条推理**。

LIVE_CONTROL（36 位 body，运行时生成，不入库）三种跑法同报一枚 `github-pat`：

```
throwaway git repo, git 模式,      shipped -> exit=1 findings=1 ['github-pat'] file=sub/planted_ghp.py
同一 repo,          --no-git 模式, shipped -> exit=1 findings=1 ['github-pat']
同一 repo,          --no-git 模式, bare    -> exit=1 findings=1 ['github-pat']
```

IN_PAYLOAD_CONTROL：把同一枚 token 种进**载荷副本**再扫，分子分母同时动，看完删掉：

```
副本 167 files / 10748640 bytes  ->  168 files / 10748697 bytes（+57 = 那一行 `SEC_API_KEY = "ghp_…"` 的字节数）
findings=1 ['github-pat'] file=docs/evidence/C126/sec-insider-witness-20261017/probes/planted_probe.py
planted_present_after_remove=NO
副本里真正入库的两枚探针在删除后逐枚核过未动：
  carrier_falsification=45766f9690a21695  acceptance_delta_and_phase_floor=5dc1533c463b16c6
```

上一段的第一版还留着一处仪器缺陷，一并记在这里以免重复犯：差分臂最初写成 `cp /tmp/… ` 到不存在的
目标目录，`cp` 失败后四个臂照样各打了一行 `findings=0` —— 扫的是空目录。四条 0 全部作废、
本文件不收录，改为脚本内 `[ -s … ] || { echo PLANT_WRITE_FAILED; exit 8; }` 先证写入存在再扫。
这与我此前记过的"沉默的默认值伪造 0"是同一族：臂的 0 只有在"扫的东西确实在那里"时才是读数。

## 3. 取数配方（可重跑）

```bash
cd /Users/yunjinqi/Documents/new_projects/opendata
{ git -c core.quotepath=off diff --name-only
  git -c core.quotepath=off ls-files --others --exclude-standard \
      -- docs/evidence/C101 docs/evidence/C126 scripts/quality docs/迭代计划
} | grep -E '^(scripts/quality/|docs/evidence/(C101|C126)/|docs/迭代计划/)' | sort -u \
  > /tmp/w21_payload.txt

rm -rf /tmp/c126_scan
while IFS= read -r f; do mkdir -p "/tmp/c126_scan/$(dirname "$f")"; cp -p "$f" "/tmp/c126_scan/$f"; done \
  < /tmp/w21_payload.txt
find /tmp/c126_scan -type f | wc -l           # 必须等于 wc -l < /tmp/w21_payload.txt
printf '[extend]\nuseDefault = true\n' > /tmp/gitleaks_bare.toml

for cfg in .gitleaks.toml /tmp/gitleaks_bare.toml; do
  gitleaks detect --no-git --source /tmp/c126_scan --config "$cfg" --redact -f json \
    --report-path /tmp/round.json >/dev/null 2>&1
  echo "cfg=$cfg exit=$? findings=$(/Users/yunjinqi/opt/anaconda3/envs/py313/bin/python -c \
    "import json;print(len(json.load(open('/tmp/round.json'))))")"
done
```

`--report-path` 是必需的：不带它 stdout 为空，判定只能落在 stderr 的 `no leaks found` /
`leaks found: N` 上（C125 §3 记过一次把"JSON 解析失败"读成"没有 finding"）。
配方脚本本身在 `.w21-scratch/`（`w21_scan.sh`、`w21_differential.sh`、`w21_diff_arm.sh`，加上 R-final
的 `w21_rfinal2.sh` 与两条死 grep/`RuleID` 差分臂），提交前随整个 scratch 目录一起删除 —— 它们不进
载荷（`.w21-scratch/` 不匹配上面那条 `grep -E` 前缀），也不是证据面，只是取数工具。删除后配方要靠
这一节自己复算：把上面每条 `echo` 的读数当作断言，重跑即知真假。

## 5. 与 C125 凭证面的差异（一句话）

C125 的两臂同为 0，理由句（"绝大多数改动就是被豁免的那个形状"）本波被普查否证 —— 豁免在本仓
证据写法下命中 0 行；能力仍在，用合成人测出来了。C126 的两臂同为 0，理由是同一份普查、一条能
不为零的对照臂，以及一份分母自证：`find` 逐枚求和的字节等于 gitleaks 自己 stderr 上打的
`scanned ~N bytes`，枚数等于配方清单的行数（R1 与 R-final 各证一次，N 不落本文件，理由见 §4）。
