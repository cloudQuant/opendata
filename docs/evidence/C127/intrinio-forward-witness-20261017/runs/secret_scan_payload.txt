## 1. 两臂，以及本波为什么 bare 臂不承重

shipped `.gitleaks.toml` 只有一条 `[[allowlists]]`（`regexTarget = "line"`，正则从**该 block 内**
取出，源码长 65：`"[^"\n]{2,160}?/[^"\n]{1,160}?\.[A-Za-z0-9]{1,6}": "[0-9a-f]{64}"`），
豁免的是"同一行里 `路径 → 64 位十六进制`"这一形状。C125 的理由句在本波被普查否证：

```
本波载荷 248 枚  行=247659  含引号 64hex 的行=63667  命中豁免正则的行=0
```

命中 0 的原因在产物的写法里：producer 用 `json.dumps(..., indent=2)` 一键一行，摘要写成
`"after_sha256": "<64hex>",` 与 `"path": "opendata/data/models/intrinio_iter2.py"` 两行，
路径与摘要不同行，那条 line-targeted 正则结构上抓不到本仓的证据 JSON。
所以本波两臂同为 0 **不是**"豁免吃掉了凭证"。

豁免的能力另用合成人测（token 运行时生成，逐**文件**分目录扫，见 §2 那条取数缺陷）：

| 版面 | shipped 臂 | bare 臂 |
| --- | --- | --- |
| token 与 `"路径": "<64hex>"` 同一行 | exit=0 findings=0 rules=[] | exit=1 findings=1 ['github-pat@carrier.txt'] |
| token 单独一行（pair 仍在文件里） | exit=1 findings=1 ['github-pat@carrier.txt'] | exit=1 findings=1 ['github-pat@carrier.txt'] |

即：这条豁免确实能在"凭证与摘要对同行"时把真凭证吃掉（`regexTarget = "line"` 的固有后果，
`.gitleaks.toml` 170-178 行的注释也是这么写的）；本波载荷里这种同行行数为 0，所以第二臂是保险，
不是本波的判据。把这句写成判据而不是沿用 C125 的理由句，是本波凭证面真正落下的东西。

## 2. 本波取数里我自己的三处仪器缺陷（读数作废并重取）

三处都不是产品的读数，是仪器的读数，形状与既往"沉默的默认值伪造 0"同源，一并记下免得重复犯。

1. **豁免普查第一版用了错的正则，产出一个假 0。** 提取语句写成
   `re.search(r"regexes = \[\s*'''(.+?)'''", cfg, re.S)`，打在**全文第一个** `regexes = [` 上 ——
   那是某条 `[[rules]]` 自己的正则（源码长 39），不是 `[[allowlists]]` block 里那条（源码长 65）。
   `count[[rules]]=2`、`count[[allowlists]]=1`，所以第一个命中必然落在 rule 上。
   假 0 的暴露方式不是它自己，是随后的容量臂：同一条错正则对我手造的 pair 行读 `False`，
   而 gitleaks 的行为说明该行本该匹配。**任何一条以正则取得的 0，必须先看这条正则在一个人
   确实希望它匹配的行上读不读 True** —— 改正后从 `cfg[cfg.rfind("[[allowlists]]"):]` 起取，
   容量行读 `True`，载荷普查仍是 0（`files=248 total_lines=247659 hex_lines=63667 hits=0`）。
2. **容量臂第一版把两枚文件放进同一个扫描目录**，于是 `findings=1 (shipped) / 2 (bare)` 是**聚合数**，
   无法归责到"同行"还是"单独一行"。我一度据此以为本波容量读数与 C126/C75 记录的形状相矛盾。
   改为每枚文件独占一个目录后，归责清楚：shipped 在同行版面 0、在独行版面 1，与记录一致。
   教训的形状：**臂的数必须落在臂的对象上**；两枚载体一次扫，得到的是一条不属于任何载体的数。
3. **R-final 第一次跑在空目录上，打出两条看起来完全正常的 0。** 上一条命令因 zsh 引号错误
   （`$( … )` 里嵌了双引号）在写清单之前中止，`/tmp/w22_payload_final.txt` 根本没被创建；
   `while read … < 该文件` 于是循环 0 次，副本目录空，两臂各 `exit=0 findings=0`，
   末行还补一句 `scanned ~0 bytes (0)`。这一条与 C126 §2 记的"cp 到不存在的目标目录、四臂各打
   findings=0"是**同一族的复发**，所以我这次把守卫写进取数脚本本身而不是靠记忆：

   ```python
   list_n = len([x for x in LIST.read_text().splitlines() if x.strip()])
   files = [p for p in SRC.rglob("*") if p.is_file()]
   if len(files) != list_n or sum(p.stat().st_size for p in files) == 0:
       print("PAYLOAD_GUARD_FAILED …"); sys.exit(9)     # 扫描之前先证要扫的东西确实在那里
   ```

   改正后 R-final 的守卫读 `PAYLOAD_GUARD_OK list_lines=250 find_count=250 bytes=13351638`，
   与 gitleaks 自报的 `scanned ~13351638 bytes` 同数。`findings=0` 在这条守卫之前不是一条读数。
   这一对字节数是**那一代**副本的读数（本节之后本文件还被改写过，definitive 那次比它大）；
   枚数 250 稳定、字节数按 §4 的理由不落回本文件。

## 3. 对照臂：这台仪器必须能不为零

```
DEAD_CONTROL_1  AWS 文档示例值 AKIAIOSFODNN7EXAMPLE + wJalrXUtnFEMI/…EXAMPLEKEY
                -> shipped exit=0 findings=0 / bare exit=0 findings=0
                （默认规则把文档示例值本身列了豁免；本波重测仍为 0，C125 登记的第一条假控制还活着）
ghp_ 长度复核（body 全数字，一次性生成，不入库）：
                +36 -> shipped 1 ['github-pat']        bare 1 ['github-pat']
                +40 -> shipped 2 ['generic-api-key','github-pat']  bare 同读数
                +66 -> shipped 1 ['github-pat']        bare 1 ['github-pat']
                （这是 C126 §2 对 C125 那条"超长落不进定长"更正的再证：规则是无前缀锚定的
                 `ghp_[0-9A-Za-z]{36}`，40 位串里含可匹配的 36 位前缀，照样报。）
```

IN_PAYLOAD_CONTROL：把一枚 `ghp_`+36 种进**载荷副本**再扫，分子分母同时动，看完删掉：

```

bare    exit=1 findings=1 ['github-pat'] 同一枚 file

```

种入前先证写入存在（`[ -s ] || PLANT_WRITE_FAILED; exit 8`），这是 C126 §2 末记的那条
"扫空目录也能打四条 findings=0"的形状，本波直接把它编进取数脚本而不是靠记忆。

R-final 的读数不落回任何入库载体：本文件若再被写入就又一次改变了被扫的字节。它落在这次会话的

其中任何一条可报行都会被 §3 的对照臂以同一规则报出，所以两臂的 0 不是"看不见"。

## 5. 取数配方（可重跑）

```bash
cd /Users/yunjinqi/Documents/new_projects/opendata
{ git -c core.quotepath=off diff --name-only
  git -c core.quotepath=off ls-files --others --exclude-standard \
      -- docs/evidence/C101 docs/evidence/C127 scripts/quality opendata docs/迭代计划
} | grep -E '^(scripts/quality/|docs/evidence/(C101|C127)/|docs/迭代计划/|opendata/data/providers/intrinio/)' \
  | sort -u > /tmp/w22_payload.txt

rm -rf /tmp/w22_scan; mkdir -p /tmp/w22_scan
while IFS= read -r f; do
  [ -f "$f" ] || { echo "MISSING_FROM_WORKTREE: $f"; exit 7; }
  mkdir -p "/tmp/w22_scan/$(dirname "$f")"; cp -p "$f" "/tmp/w22_scan/$f"
done < /tmp/w22_payload.txt
find /tmp/w22_scan -type f | wc -l            # 必须等于 wc -l < /tmp/w22_payload.txt
(cd /tmp/w22_scan && find . -type f -exec cat {} + | wc -c)   # 必须等于 gitleaks stderr 的 scanned ~N bytes
printf '[extend]\nuseDefault = true\n' > /tmp/gitleaks_bare.toml

for cfg in .gitleaks.toml /tmp/gitleaks_bare.toml; do
  n=$(basename "$cfg"); gitleaks detect --no-git --source /tmp/w22_scan --config "$cfg" \
      --redact -f json --report-path "/tmp/w22_round_${n}.json" >/dev/null 2>&1
  echo "cfg=$n exit=$? findings=$($PY -c "import json;print(len(json.load(open('/tmp/w22_round_${n}.json'))))")"
done
```

正则的取法是本波最容易失手的一步，写成可复算的形式：

```python
cfg = pathlib.Path(".gitleaks.toml").read_text(encoding="utf-8")
src = re.search(r"regexes = \[\s*'''(.+?)'''", cfg[cfg.rfind("[[allowlists]]"):], re.S).group(1)
assert len(src) == 65          # 39 说明你取到了 rules 上，普查产出的 0 是假的
```

`--report-path` 是必需的：不带它 stdout 为空，判定只能落在 stderr 的 `no leaks found` /
`leaks found: N` 上（C125 §3 记过一次把"JSON 解析失败"读成"没有 finding"）。规则名取 `RuleID`，
不是 `ruleId`（gitleaks 8.30.1 的报告键；C126 §4 记过这条死键）。配方脚本在 `/tmp/w22_ctl.py`，
不在仓内、不进载荷；删除后要靠这一节自己复算：把上面每条 echo 的读数当作断言，重跑即知真假。
