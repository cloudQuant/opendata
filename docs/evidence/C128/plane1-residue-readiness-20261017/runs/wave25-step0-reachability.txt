Why this carrier exists
-----------------------
Section 85.8 armed a wave and section 86.8 narrowed the predicate to the *cheapest* rows, but cost
and reachability are different axes. The pricing census answers "what has to be written"; it does
not answer "which witness mechanism can actually execute the row". Step 0 answers the second
question with the shipped runner's own fake surface, for the whole 350-identity population rather
than for the three providers spot-checked in wave 24.

Fix that this run depends on
----------------------------
probes/seam_surface_match.py previously had two verdicts and derived WITNESSABLE from
`not missing`, where `missing = verbs - fake_surface`. An empty `verbs` set -- a provider that
never calls `get_shared_http_client()` -- made `missing` empty, so the probe reported WITNESSABLE
for a provider the seam does not reach at all. That is a vacuous truth, and it was measured, not
assumed: the first five-arm run printed `verbs=[] missing=[] verdict=WITNESSABLE` for yfinance and
nasdaq and exited 1 only because the positive control (the provider must show accepted rows) caught
it. The probe now has a third verdict, NO_SEAM_VERBS_MEASURED, emitted when the AST collection
returns no verbs. Controls 1 and 2 below are the two-sided proof that the new branch is live and
that the WITNESSABLE branch did not simply get muted.

  the shared `_engine` package and `akshare`/`ths`, which hold zero of the 350 identities) plus the
  2 inventory names with no directory. Providers whose name appears only on disk are printed in
  disk_only; nothing is silently dropped.
