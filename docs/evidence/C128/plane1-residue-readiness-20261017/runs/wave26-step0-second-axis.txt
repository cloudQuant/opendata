The four axes
-------------
``bound``            ``ProviderRegistry.resolve_model`` returns a fetcher for the identity.
``ruled_out``        the provider's own ``NOT_DECL*`` ledger dict carries the identity (the ledger
                     is spelled ``NOT_DECLARABLE`` in cboe and intrinio and ``NOT_DECLARED`` in
                     econdb, so the attribute *prefix* is matched, never one hardcoded name).
``guard``            this row's own fetcher class holds a refusal that a fixture-document tamper can
                     trip: either a code-carrying raise in ``transform_data`` (the engine hands that
                     method the decoded payload, pasted verbatim below) or one in ``extract_data`` on a
                     line *after* that function's governed-client call.
``row_class``        the class the bound fetcher constructs must **be** ``contract_model(domain)``.
                     Without this the first three axes price a declaration that the service leg then
                     refuses.

The engine leg that makes ``transform_data`` reachable, read from product code
------------------------------------------------------------------------------
``opendata/data/protocol.py`` lines 312-317, inside the synchronous ``fetch`` pipeline (declared at
``:282``). The async entry ``_fetch_async`` (``:399``) makes the same pair of calls on both of its
legs -- ``:477`` then ``:486`` for a sync fetcher run in the bounded pool, ``extract_data_async`` at
``:540`` then ``:559`` for a native async fetcher -- so every phase the witness recorder drives lands
on one of these:

 312|                 params = self.transform_query(**kwargs)
 313|                 validate_scope_grants(capture_request_scopes())
 314|                 raw = self.extract_data(params, context)
 315|                 return self.transform_data(raw, params)

So ``extract_data`` and ``transform_data`` are both called by the engine on every fetch, in that
order, with the same ``params`` object -- which is why a raise reachable from either of them is a
guard a tamper can trip, and why "the class exists and the fetcher runs" is not yet a claim that the
row is declarable.
