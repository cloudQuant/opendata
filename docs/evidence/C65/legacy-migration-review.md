当前只有 `STOCK_ZH_A_HIST → ods_stock_daily_akshare` 一条明确旧表映射；其余 1,025 表逐项记录为“无已批准迁移映射或目标 DDL，暂不搬移、保留源表”。这完成了目录与当前映射覆盖审查，不表示这些表已逐字段迁移、已归档或不再有业务用途。normalize YAML 中存在某个域也不等于旧表已有搬移路径。

已映射表实际为 617,371 行、617,371 个 `(股票代码, 日期)` 键，日期 2026-01-05 至 2026-07-21。旧表主键是 `R_ID`；业务键唯一性来自本轮全量 DISTINCT 查询，不能由源 PK 推断。12 个原始字段存在；日期为 text、换手率为 text、成交量为 bigint，目标分别为 date/double/double，且目标 OHLC/成交量/成交额不可 NULL，必须检查无效日期、空值、非有限数值和转换精度。原始 ODS 成交量不可提前乘 mapping 的 100 倍；该换算在契约归一阶段进行。

C3 `migrate-full.json` 的 rows_affected=607,371 与 `verify-full.json` 的源/目标 617,371 相差 10,000，历史 README 又称目标为空。没有材料解释差异，不能补写原因或修改历史日志。历史 verify 只摘要前 1,000 个 distinct key、目标按全部 `_source=akshare` 统计，没有验证所有12字段或本批次。因此本轮另做空隔离目标迁移和全量字段对账，实际运行结果为 FAIL，详细原因与完整空值普查见下文。

当前 native 连接的数据库 ACL 不是只读。本文所有查询使用只读事务并未写 native，但不能把会话只读说成旧库账户/库权限已锁定。AC-15|01 的权限限制、AC-15|02 的实际全量迁移及最终删除决定均不能由目录盘点代替。旧工具 `--drop TABLE --yes` 不绑定验证凭证，本轮禁止使用。

## 实际隔离迁移与全字段质量结果

工具 `scripts/ops/migrate_legacy_stock_daily.py` 已经主线程审阅并独立运行30项offline守卫测试（PASS），然后实际连接native3306只读快照和已迁移的空隔离目标。`legacy-transfer-current.json` 为 FAIL：`invalid_numeric_field_成交额`；源617371行、目标初始0、写入0。工具拒绝将NULL隐式转换为0，没有发出DROP或native数据写入。

随后独立只读聚合核对全部12业务字段，见 `legacy-field-quality-census.json`：日期/股票代码/OHLC/成交量均无NULL；成交额、振幅、涨跌幅、涨跌额各616694行NULL；换手率617356行NULL；日期格式和六位代码非法数均0。成交额是新ODS必填字段，因此617371行不能按当前映射全部迁入。其余可空字段仍按原值保留，不能用可空列问题掩盖必填列冲突。

这说明历史键/行数相等不足以证明业务字段迁移正确。既有C3证据不能据本轮结果反写为通过或解释历史10,000行差异。本轮完整结构目录和质量审查已经实际执行；值迁移仍FAIL，1025个无当前映射旧表继续逐项保留。补采、重新定义原始ODS可空契约或保留独立原始档案需要先完成相应字段设计和来源对账，不能替原数据填零或重命名来源。最终删除仍未授权。
