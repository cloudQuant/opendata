## Declarations, each re-derived rather than quoted

* the two old pins are the hashes of blobs at ``3f05f63`` and ``60148ce``, and those revisions are
  what the screen's own ``git show`` calls returned -- the revision constants in the screen source
  are the only typed inputs, and the fence re-checks them;
* both new pins equal sha256(disk), sha256(HEAD blob) and sha256(the blob of the commit that moved
  the bytes) -- three separate digest claims, not one;
* brand_lines, brand_occurrences and load_shape_lines are unchanged for both files, and the
  scanner's ``(module, kind)`` finding multiset is identical (1 and 13);
* the total-line faces did move (a2_check 364 -> 390, acceptance_item_probe 16134 -> 16468)
  because C77 rewrote the bandit leg and C78 rewrote the AC-10|03 judge; what has to be invariant
  is the reference content, and it is;
* the pin judge bites: forging one entry's digest returns exactly
  ``stale sha256: <that path>``, once per forged path, 2 of 2 arms -- the same message that stopped
  run 6, so the zero on the re-pinned policy is a measurement and not a judge that cannot fail;
* the content comparator bites too: one added ``import akshare`` plus one module-path string
  produces 4 problems.

## Established / not established

Established: run 6's stop was a pin-staleness refusal on a clean tree at ``2535178``, not a
judgement failure; the two drifted files carry identical reference content under the repo's own
scanner; the re-pin is therefore a re-pin and not a new approval; the members that ran (1 and 2)
now read green on the re-pinned policy.

Not established:

- that the other 85 pins are *reviewed* rather than merely *current* -- this screen only proved
  that the two entries it touched were re-pinnable; a current digest is not an approval;
- that the pin judge is sufficient: ``reference_policy_problems`` was called without
  ``actual_hit_paths``, so the bidirectional hit/register reconciliation arm is not exercised here
  (member 2's own run does exercise it, and that run is what this archive is waiting to see green);
- that gate run 6 (the retry) is green -- it had not started when this file was written;
- that the round label ``C78`` is right for this witness. It is this round's directory, and the
  re-pin belongs to the same tree as the AC-10|03 rewrite that caused the drift.
