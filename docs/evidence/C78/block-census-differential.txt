## The finding, stated as the arithmetic the body supports

The baseline tree is **not** the thing that changed. All 121 file digests in the archived C65
manifest match the bytes on disk today (121/121), and the OpenBB checkout is still at
``3e071fcc2cd9…``, the same commit the artifact pins (``equal = True``). So the three
block counts below are three readings of one identical population:

| enumerator | blocks over the 41-node floor |
| --- | --- |
| shipped ``_blocks_and_imports`` (builder added in ``60148ce``, C75) | 1105 |
| reference written from the archived artifact's own ``method`` text | 1279 |
| what the archived C65 artifact recorded | 1227 |

93 of 121 files disagree between the shipped enumerator and the documented method,
and the histogram localises the whole difference to **one block kind**: ``ClassDef.body``, shipped
0 vs reference 174. Every other kind matches exactly (``function_body``
348 on both sides (reference 348), ``For.body``, ``If.body``,
``If.orelse``, ``Try.body``, ``Try.handlers``, ``ExceptHandler.body``, ``With.body``,
``AsyncWith.body``, ``While.body``), and the identity ``shipped + class_delta == reference`` is
checked by the archive builder, not asserted here.

Neither shipped code nor the documented method reproduces the archived 1227. The archived
number sits between them, so whatever produced it in C65 emitted *some* but not all class-body blocks
(122 of 174), and that code is not in the tree -- the builder file was
added whole in ``60148ce``, and its docstring's claim to "follow the archived C65 method" is a claim
about intent, which this screen falsifies on counts.

## What that does and does not cost

It does **not** mean the shipped screen has a copy-detection hole at member granularity: the shipped
``walk`` descends into class bodies and emits each nested ``body``/``orelse``/``finalbody``/
``handlers``/``cases`` list, so every statement list *inside* a class is still compared one by one.
What is lost is the class body as a single comparison unit -- 174 blocks in the pinned
baseline, and the same granularity gap on the local side (1105 baseline blocks and 521 local
blocks are the shipped-arm numbers today). A whole-copied class is therefore detected only through
its members, never as a whole.

It does mean the sentence "读数面已可复算" in the AC-10|03 ledger reason was too strong. Recomputing
with the shipped builder is self-consistent; it does not reproduce the archived artifact's census, so
the archived ``review_candidates = 0`` and today's ``8`` are outputs of two different screeners and
cannot be cited against each other. The honest face is: a zero recorded by code that is no longer in
the tree, over 7 packages / 71 files, at a HEAD nine days and 400-some provider files away.
