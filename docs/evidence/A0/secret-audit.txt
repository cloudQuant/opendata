## 5. 白名单收紧（本轮修正）

旧白名单为 `\.env\.example$`、`^docs/`、`^tests/`、`^THIRD_PARTY_NOTICES\.md$`、`^README\.md$`，
**覆盖过宽**：`^docs/` 使得 §1 备注的真实 token 字面量长期藏在证据文件里而不被扫描。

实测后收紧为**只保留确有误报的项**（证据见下）：

| 保留项 | 理由 |
|--------|------|
| `\.env\.example$` | 按设计只含占位符（`change-me` 等） |
| `\.egg-info/` | `pip install -e .` 生成的构建产物（已被 gitignore），内嵌 README 的 curl 示例 |

去掉 `^docs/`、`^tests/`、`^THIRD_PARTY_NOTICES\.md$`、`^README\.md$` 后实测：

```text
去掉 ^tests/ 后工作区 findings = 1（仅 docs/evidence/A0/secret-audit.txt 的旧 token 字面量）
即 tests/ 与 .md 本身不产生任何 gitleaks 命中
```

根目录 `QUICKSTART.md` 等文档确有 `curl -H "Authorization: Bearer <token>"` 占位示例，
若被 `curl-auth-header` 规则命中，**按规则**放行而不是按目录放行（见 `.gitleaks.toml`）。

> 残留限制：放入白名单的路径/规则内的真实凭证仍不会被本地或 CI 扫描拦截。
> 处置原则是**移除凭证本身**，白名单只用于确有误报的占位符与生成产物。
