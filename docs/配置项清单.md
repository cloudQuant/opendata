# opendata 配置项清单（AC-19 / FR-21）

> 版本：v1.0
> 日期：2026-09-24
> 生效方式：配置经 `opendata/core/config.py`（pydantic-settings）读取；键名一律为环境变量全大写（如 `app_debug` → `APP_DEBUG`）。修改配置后需重启后端进程生效（除标注"热加载"者外）。
> 生成方式：`python -c "from opendata.core.config import settings; ..."` 枚举 `settings.model_fields`，人工补充生效方式与影响。

## 一、应用与运行

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `APP_NAME` | 应用名（API title、日志、邮件署名等） | `opendata` | 品牌相关展示 |
| `APP_VERSION` | 应用版本 | `0.1.0` | API 版本号 |
| `APP_ENV` | 运行环境（`development`/`production`） | `development` | 生产环境强制校验 `SECRET_KEY` 非默认值；影响部分校验分支 |
| `APP_DEBUG` | 调试模式 | `False` | 开启则暴露 `/docs`、`/redoc`，SQL 回显；**生产必须关闭** |
| `HOST` | 服务监听地址 | `0.0.0.0` | 部署绑定 |
| `PORT` | 服务端口 | `8000` | 部署绑定 |
| `WORKERS` | worker 进程数 | `1` | **设计约束：仅支持单进程**（D8）。多 worker 会破坏调度与推送语义 |

## 二、数据库（双库）

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `MYSQL_HOST` / `MYSQL_PORT` | 主库地址/端口 | `localhost` / `3306` | 主库（业务表）连接 |
| `MYSQL_USER` / `MYSQL_PASSWORD` | 主库账号 | `root` / 空 | 凭证；生产必须强口令注入 |
| `MYSQL_DATABASE` | 主库名 | `opendata` | 业务表所在库 |
| `DATA_MYSQL_HOST` / `DATA_MYSQL_PORT` | 数仓库地址/端口 | `localhost` / `3306` | 数仓（ods/dwd）连接 |
| `DATA_MYSQL_USER` / `DATA_MYSQL_PASSWORD` | 数仓账号 | `root` / 空 | 凭证 |
| `DATA_MYSQL_DATABASE` | 数仓库名 | `opendata_data` | 数仓表所在库；与 `alembic_data.ini` 一致 |
| `DATABASE_POOL_SIZE` / `DATABASE_MAX_OVERFLOW` | 连接池大小/溢出 | `5` / `10` | 高并发下的连接池水位 |

每日逻辑备份由可选 Compose `backup` profile 执行。默认凭证回退到应用数据库账号；生产
应配置独立的 `BACKUP_MYSQL_USER` / `BACKUP_MYSQL_PASSWORD` 与
`BACKUP_DATA_MYSQL_USER` / `BACKUP_DATA_MYSQL_PASSWORD`，并按备份要求授权。保留天数由
`BACKUP_RETENTION_DAYS` 控制。该 profile 默认不启动，启用方式与权限细节见
[备份与恢复运维手册](operations-backup-restore.md)。

> 四个配置面必须一致：`config.py` 默认值、`.env.example`、`docker-compose.yml`、`init.sql`（AC-1）。

## 三、安全与认证

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `SECRET_KEY` | JWT 签名密钥 | 内置默认值 | **生产必须替换**；泄露即身份系统失守 |
| `ALGORITHM` | JWT 算法 | `HS256` | 令牌签发/校验 |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 访问令牌有效期 | `1440` | 登录态时长 |
| `REFRESH_TOKEN_EXPIRE_DAYS` | 刷新令牌有效期 | `30` | 会话续期窗口 |
| `API_KEY_PEPPER` | API Key 哈希加盐 | 回退 `SECRET_KEY` | 改后旧 Key 全部失效，需轮换 |
| `API_KEY_FAILURE_DELAY_SECONDS` | API Key 认证失败统一延迟 | `0.05` | 防枚举；增大提升安全、影响失败路径响应 |
| `CORS_ORIGINS` | 允许的跨域来源 | 空 | 前端跨域；`*` 需谨慎 |
| `CORS_ALLOW_CREDENTIALS` | 允许跨域携带凭证 | `True` | 与 `CORS_ORIGINS` 组合 |

## 四、限流与缓存

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `RATE_LIMIT_PER_MINUTE` | 每用户每分钟限流 | `100` | API 峰值吞吐 |
| `RATE_LIMIT_BURST` | 突发容量 | `200` | 短时突发 |
| `REDIS_URL` | Redis 连接串 | 空 | 空则令牌黑名单/推送为进程内实现；**多进程部署必须配 Redis**（D8 演进项） |
| `CACHE_DIR` | 原始响应缓存根目录（兼容 `OPENDATA_CACHE_DIR`） | `~/.cache/opendata` | 缓存落盘位置（不入库） |
| `RAW_RESPONSE_CACHE_ENABLED` | 是否缓存成功 GET 的原始响应 | `False` | 显式开启后使用 TTL 缓存；不缓存归一化数据或复权查询结果 |
| `CACHE_TTL_SECONDS` | 原始响应缓存 TTL | `900` | 缓存命中率与新鲜度权衡；**水位真相源始终是 ods** |

## 五、调度与任务

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `ENABLE_SCHEDULER` | 调度归属显式开关 | 未设置 | **生产必须显式配置**；未设置时调度不启动（设计 §9.3 防裂脑） |
| `SCHEDULER_BOOTSTRAP_ON_STARTUP` | 启动时装载调度任务 | `True` | 与 `ENABLE_SCHEDULER` 配合 |
| `SCHEDULER_MAX_WORKERS` | 任务并发 worker | `3` | 跑批并发度 |
| `PATROL_ENABLED` | 是否主动运行每日 provider 巡检 | `False` | 默认禁用、仅报告 disabled；显式开启后只探测有验证和查询配置的 P0 capability |
| `PATROL_FAILURE_ALERT_THRESHOLD` | 连续失败告警阈值 | `2` 次 | 达到阈值后通过 WebSocket 广播；计数持久化在 `DATA_DIR/provider_patrol_failures.json` |
| `TASK_RETRY_MAX_ATTEMPTS` | 任务最大重试次数 | `3` | 失败任务自动重试次数 |
| `TASK_RETRY_BASE_DELAY` | 重试基础退避（秒） | `60` | 重试节奏 |

每日 provider 巡检的 P0 范围来自需求文档 §6.2；未标优先级的域保持 unknown。调度时点
`18:00 UTC` 是待真实业务时间校准的占位值，运维细节见[provider 巡检手册](operations-provider-patrol.md)。

## 六、数据源与 provider

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `FUYAO_API_KEY` | 同花顺扶摇 API Key | 空 | **空则 ths 源不可用**（路由跳过 + 醒目告警，AC-7） |
| `FUYAO_API_BASE_URL` | 扶摇 API 基址 | `https://fuyao.aicubes.cn` | 联调/镜像环境 |
| `FRED_API_KEY` | FRED web service Key | 空 | 空则 fred 源不可用（R2） |
| `FUYAO_API_KEY_EXPIRES_AT` / `FRED_API_KEY_EXPIRES_AT` | issuer 提供的 Key 到期日（ISO 日期） | 未知 | 仅按元数据预警；不代表有效性或剩余额度检查 |
| `KEY_EXPIRY_WARNING_DAYS` | 到期前预警窗口 | `14` 天 | 必须为正数 |
| `KEY_HEALTH_OBSERVATION_TTL_HOURS` | 手工巡检失败观察保留时长 | `24` 小时 | 超时后状态回到未知，不当作上游恢复 |
| `FRED_API_BASE_URL` | FRED 基址 | `https://api.stlouisfed.org` | 联调 |
| `ECB_API_BASE_URL` | ECB 数据门户基址 | 官方默认 | 联调 |
| `IMF_API_BASE_URL` | IMF DataMapper 基址 | 官方默认 | 联调 |
| `OECD_API_BASE_URL` | OECD SDMX 基址 | 官方默认 | 联调 |
| `OECD_CPI_FLOW` | OECD CPI 数据流 id | `HICP` | 数据口径 |
| `AKSHARE_TIMEOUT` / `AKSHARE_CALL_TIMEOUT` | akshare 请求/调用超时 | `120` | 上游调用超时 |
| `AKSHARE_RETRY_ATTEMPTS` | akshare 重试次数 | `3` | 上游失败恢复 |

> 无 Key 的 provider 按 AC-10 标注 `notes="on-demand"` 不参与 auto 路由；Key 缺失不阻塞其它源。

## 七、保留策略与存储

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `RETENTION_DIFF_REPORT_DAYS` | `dq_diff_report` 聚合保留天数 | `90` | 差异明细保留窗口 |
| `RETENTION_MINUTE_YEARS` | 分钟线归档保留年限 | `10` | 分钟线文件清理窗口 |
| `RETENTION_EXECUTION_ENABLED` | 是否允许计划任务执行删除 | `False` | 默认仅报告候选数；需显式设为 `true` 才删除过期范围 |
| `DATA_DIR` | 数据存储目录 | `./data` | 本地分钟线 Parquet 根；由运维 CSV 导入器写入，没有自动上游抓取器 |
| `UPLOAD_DIR` | 上传目录 | `./uploads` | dump 导入的暂存目录 |

默认只报告候选数。删除目标限定为 `dq_diff_report`、`DATA_DIR/minute_archive` 和
`CACHE_DIR/raw_responses`；ods/dwd 等永久表不参与删除。分钟归档由运维 CSV 导入器写入，
当前没有自动上游抓取器；也没有磁盘 raw-response 缓存写入者。缓存清理不会遍历
`CACHE_DIR` 下其它目录。

备份服务通过可选 Compose profile 调度，不属于应用计划任务：

| 键名 | 含义 | 默认值 | 改动影响 |
|------|------|--------|----------|
| `BACKUP_RETENTION_DAYS` | 逻辑备份保留天数（备份脚本/Compose） | `30` | 必须为正整数 |
| `BACKUP_ENV_FILE` | 备份脚本读取的 dotenv 路径 | 项目根 `.env` | 显式空值跳过 dotenv；调用环境变量优先于 dotenv |
