# 深交所退市证券候选种子校验运维说明

`opendata.data.szse_delisted_seed.validate_szse_delisted_seed` 是一个有界输入校验函数，用于校验调用方提供的深交所 2023 年鉴退市证券混合表候选行，以及可选的证券类别和日期声明。它不会自行进行文件、数据库、环境变量或网络 I/O，但会消费调用方传入的候选行和声明 iterable；自定义 iterable 的迭代逻辑也可能执行调用方代码。它只检查声明的结构和相互关系，不读取年鉴 PDF，也不验证输入事实。

## 输入声明与固定来源档案

当前内置来源档案将 `source_id=szse.yearbook.2023` 固定关联到 SHA-256 `954a719859b3767ffa3ed4d1ca3b50803549bcaca6366925a194d27f12be0bb4`。校验器要求候选行提交的 `source_id` 和 `pdf_sha256` 与这组值相符。该检查只证明输入字段与代码中的固定档案相符：校验器不打开或散列 PDF，不核实文件来源、PDF 内容、提取出来的原文、证券代码、页码或解析后的日期。

年鉴表是混合证券候选来源。六位代码和发行人名称只用于候选行及外部声明之间的精确匹配，不足以证明 A 股类别。候选记录需保留一基 PDF 页码、印刷页码、行定位符和表中证券类别原文（如果有）。印刷页码和 PDF 页码是不同字段，不应互相替代。

## 分类与日期处理

没有类别声明的行保持 `candidate`。调用方可以提交 `CallerAshareClassAttestation` 声明 `A`、`B`、`OTHER` 或 `UNRESOLVED`，并明确填写 `market=CN`、`exchange=XSHE`。输出中的 `a_share_class_attested`、`non_a_share_class_attested` 和 `class_unresolved` 只复述调用方声明，不能当作校验器独立确认过的证券分类。

声明中的来源标识、文档 SHA、定位符、引用、审阅人标识及独立性布尔值都由调用方提供。校验器仅检查这些字段的格式、类别声明是否填写了独立性为真、来源标识和文档 SHA 是否与年鉴声明不同，以及代码和发行人名称是否精确匹配。它不读取声明的来源材料，也不核实审阅人身份、来源真实性或审阅是否真的独立。因此，`CallerAshareClassAttestation` 是调用方声明，不是经过认证的审阅记录。

年鉴候选行和外部声明分别保存三个日期：`listing_date`（上市日期）、`last_trade_date`（最后交易日）和 `termination_date`（终止上市日期）。每项日期事实保留原始文本、可选的 `datetime.date` 解析值和字段定位符。校验器不会从原始文本解析日期，也不会判断解析值是否抄录正确；日期比较只比较调用方给出的解析值。比较结果可能为 `not_compared`、`incomplete`、`agrees` 或 `disagrees`。若有冲突，输出列出冲突字段；冲突不会改写年鉴日期，也不会自动撤销类别声明，需由人工查回原始证据后处理。

校验器只按已提供的日期拒绝明显倒置的生命周期顺序。日期格式或顺序检查通过，不等于日期原文或证券生命周期已核实。未知日期应保持未知，不要根据相邻日期、最新行情或常识补造。

## 冲突处理和输出边界

函数对候选行和类别声明分别施加 20,000 行上限。它会消费传入的 iterable 以构造有界输入；生成器因此会前进，自定义 iterable 也可能在迭代时运行自己的代码。重复候选证券代码、重复类别声明、没有对应候选证券的声明、证券名称不匹配，以及同一来源、文档、PDF 页码和行定位符却指向不同证券代码的冲突，都会使整个调用抛出 `SzseDelistedSeedError`。此时没有部分审计结果可供下游继续使用；应停止处理并回查输入来源，不能选取其中一行静默放行。

审计输出按证券代码排序并分别报告候选、A 股类别已声明、非 A 股类别已声明及类别未决数量。`market_completeness` 在 `SzseDelistedSeedAudit` 构造器中不可传入，常规使用时固定为 `not_assessed`。数据类冻结和该字段设置只约束正常 Python 调用；同进程代码仍可使用 `object.__setattr__` 绕过，不能视为恶意代码安全边界。函数不会分配规范证券 ID、映射到证券注册表、更新 `instrument_reference`、写文件或数据库、访问环境变量、连接网络，亦不会证明年鉴内行集合、深交所退市集合、A 股集合或全市场集合完整。

## 推荐的使用流程

1. 在校验器之外，按项目的数据采集与证据保存流程获取、固定并核对原始年鉴 PDF；单独记录实际文件的校验值和来源。不可把代码内置的 SHA 匹配当作原始文件校验。
2. 从原始资料整理候选行，保留印刷页码、PDF 页码、表格行定位、日期原文及其单独解析值。无法确认的解析值留空。
3. 需要分类时，先依据另一份实际查阅的证据核对证券类别，并留存来源、定位和审阅记录。只有独立性已由流程外人员核实后，才由调用方填写相应声明；当前校验器自身不会完成这一步。
4. 调用 `validate_szse_delisted_seed(candidates, attestations)`。若出现重复键或来源行冲突，停止该批处理并回查原件。保留原始声明、校验输出和人工处置记录，禁止覆盖原始事实。
5. 在证券注册表或覆盖率系统使用候选结果前，另行完成规范证券 ID 规则、来源映射、来源证据验证和证券生命周期覆盖审查。当前校验结果不能直接作为注册表导入或“全量已覆盖”的依据。
